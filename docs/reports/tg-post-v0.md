# Telegram-пост — прогон spec-v0

Готов к копированию (всё ниже разделителя).

---

**Собрал Telegram-бота как агента — из спецификации, а не из промптов**

Условия задачи: минимальный harness без фреймворков (только httpx +
python-dotenv), защита от зацикливания, универсальный консольный `exec`,
пара скиллов, `/new`, хранение диалога, whitelist по tg_id. Python 3.13, uv,
Linux.

Что получилось: сначала спецификация на 113 требований с ID — точные строки
ошибок, точные порядки проверок, готовый список тестов. Дальше
claude-opus-5 (Claude Code) получил ровно один промпт,
`go docs/spec/spec-v0.md`, и собрал по ней всё: агентный
цикл с жёсткими бюджетами (8 раундов / 9 HTTP-попыток / 12 запусков
инструментов на сообщение), `exec` с process-group TERM→KILL и обрезкой вывода
по байтам, два провайдера инференса за одним интерфейсом (LM Studio /
OpenRouter), окно контекста, которое режет историю только по целым turn-группам.

Метрики:
• спека — ≈23k токенов (2081 строка, 92 КБ)
• промптов к модели — 2 (реализация + ревью)
• с первого прогона — да: все 4 гейта зелёные, 0 циклов починки
• тестов — 113, полностью офлайн
• багов — 2: агент сам поймал утечку токена бота в логи httpx; ревью в чистом
  контексте нашло тест, который не проверял то, что обязан
• реализация (claude-opus-5): 14,78M in (из них 14,52M — кэш-чтение) /
  148,5k out — харнесс счётчики агенту не отдаёт, снято с транскрипта сессии
• стоимость: flat-rate подписка; оценка по открытым API-ценам ≈ $12,6

Главный вывод: ревью в чистом контексте ловит не код, а тесты. Мутация парсера
`retry_after` оставляла 113 из 113 зелёными.
