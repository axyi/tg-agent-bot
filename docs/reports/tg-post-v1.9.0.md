tg-agent-bot v1.9.0 — RAG над документами пользователя

Условия: бот работал только с текстом чата. Нужно: загрузка
PDF/DOCX/TXT/MD, чанкинг, эмбеддинги, гибридный поиск (вектор + BM25 +
RRF), опциональный rerank, атрибуция источника в ответе, изоляция по
user_id.

Результат: /documents, /delete, upload-flow; схема БД 5→6
(documents/chunks/vectors); rag.py (vector/BM25/RRF/rerank/Searcher);
четвёртый инструмент search_documents с атрибуцией. Ретрив измерен
живьём: recall@5 = 1.000 на всех трёх режимах, MRR 0.95–1.0, page
hit-rate 1.000. 105/105 мутаций убиты, offline-гейты зелёные.

Честно, не замолчано: gate 7 (живая ретрив-оценка) красный на этом
деплое — не дефект кода, а диагностированная нестабильность длины
reasoning у thinking-модели (qwen3.8-27b): reranker иногда не
укладывается даже в увеличенный таймаут (120с вместо 20с), хотя само
ранжирование при завершении верное. Решение по gate 7 — на T13.
Раскрыто и устранено 7 operator-ratified эрратов (версия/схема тестов,
zero-chunk документ, версия-пин тест repoint на git tag), реальный баг
с getFile, 2 находки code-review (1 исправлена, 1 waived).

Метрики: исполнитель claude-sonnet-5 (Claude Code), 18 промптов
(141–158). Спека ≈204.4 КБ. Repair-бюджет: 2 из 4 (gate 7, не сошлось).
Токены: субагенты — по задаче в отчёте; оркестратор харнессом не
показывается. Стоимость: $0 — подписка, живой инференс по референсным
ценам, реальных денег не потрачено.
