# Telegram-пост v1.4

---

**Пять кандидатов на «выключить reasoning» — и ни один не выжил**

v1.3 оставил открытым главный рычаг: reasoning — 71,8% completion-токенов, но LM Studio игнорировала штатный /no_think. v1.4 — patch-релиз: найти механизм, который LM Studio реально слушается, проверить живыми парными прогонами, а не по документации.

Перебрали все 5 кандидатов (RSN-01…06):
a) chat_template_kwargs.enable_thinking=false — не сработал (2/2)
b) reasoning.effort — в доках LM Studio только low/medium/high, отключающего значения нет — unsupported
c) пустой префилл <think></think> — сработал 3/3, но ломает byte-stable префикс кэша (POL-05) — honored, но unshippable
d) /no_think в последней user-строке — не сработал (2/2)
e) настройка на уровне модели в LM Studio/lms CLI — для этой версии в документации такой настройки просто нет

Вердикт: FAIL, no honored reasoning mechanism (RSN-06 STOP). Policy/observability и прогон кандидата — not-executed по самой спеке.

Что доехало: починка ложноотрицательного S01-чека (ловил фразеологию, не смысл), свежий baseline-v1.4 ($0,003009/успех), REL-01 — таймаут больше не рассинхронизирован с лимитом токенов (120→240с по умолчанию), 68/68 мутаций, ревью с двумя реальными находками.

Метрики: claude-sonnet-5, спека 77 REQ / 1516 строк, 10 промптов, 6/6 гейтов, 728 тестов (+9 к v1.3), 68 мутаций. Токены/стоимость исполнителя — unknown, харнесс не отдаёт.
