## Goal

The clean-context review of `b959a63` returned one 🔴 against
`tests/test_v190_retrieval.py`:


Both sides of the comparison come from the function under test. A bug inside
`_rerank_response_format` — a renamed key, a wrong `type`, an off-by-one
`minimum`/`maximum` — keeps this assertion green, because the expected value
is regenerated by the same broken code. This is the exact failure mode
`standards/workflow.md` §4 names as the highest-value review target, and the
same shape both earlier v0 reviews in this lab found.

narrow and should be stated as such: that a schema is sent at all, and that
it is sized to the candidates actually passed (3), not to
`_HYBRID_CANDIDATES`. The schema's full shape is already pinned independently
in `tests/test_v191_rerank_contract.py::test_t_v191_rerank_response_format_schema_shape`,
which hand-writes the expected dict — that test keeps ownership of shape, and
this one stops duplicating it badly.
