## `devtools/rag_eval.py` (REQ-V190-EVAL-03)

`main()`: `load_config()`, build one `EmbeddingsClient` and the LLM client
exactly as `bot.py` does. Create a **temporary database**
(`tempfile.TemporaryDirectory` — this is executor tooling, EC-01's
ephemeral-file permission covers it explicitly; the context manager
removes the directory on exit): `storage.connect`,
`init_schema(embedding_dim=…, embedding_model=…)`. Index the four corpus
documents for **synthetic user id −1** through `documents.index_document`
(the real production pipeline, no Telegram involved) — pass
`started_at=time.monotonic()` per document (DOC-05's required arg) and
`progress=` a no-op sink (this script owns no status message).

For every question and each of three modes, record the **first-hit rank**:

- `vector` — `rag.vector_search` alone (RET-03), top-5.
- `hybrid` — vector + BM25 + RRF (RET-03/04/05), top-5.
- `hybrid+rerank` — the full `Searcher.search`.

**Override the deployment's retrieval config, always**: after loading
`Config`, force `rag_rerank = "on"` and `rag_top_k = 5` regardless of the
environment (otherwise `RAG_RERANK=off` would silently make
`hybrid+rerank` report plain RRF, and `RAG_TOP_K != 5` would change what
recall@5 means). **Print this override in the script's own header output**
so the run's stdout proves it happened.

**Hydration, for `vector`/`hybrid` only** (id-level modes — they produce
chunk ids, not hydrated passages): take the first five ranked ids, call
`chunks_by_ids(conn, user_id=-1, ids=…)` **exactly once per mode**, drop
ids the query didn't return, **restore the original ranked-id order**
before any scoring (the DB's row order must never become the ranking; the
tenant predicate `-1` is never dropped). `hybrid+rerank` needs none of
this — `Searcher.search` already returns hydrated `Passage`s.

**A hit is evidence, not a filename.** A passage counts only when
`filename == expected_source` **and** its text contains
`expected_evidence` (case-insensitive, whitespace-normalised comparison).
First-hit rank = 1-based position of the first such passage in that mode's
top-5, or none.

**Metrics, over the ten answerable items**: `recall@5` = hits ÷ 10;
`MRR` = mean(1/first-hit-rank, 0 for a miss); `page hit-rate` = share of
the **three PDF items** whose first hit has `page == expected_page`. All
three reported per mode. The two null items are **advisory only** — report
"no passage from any file" vs "passages returned", never scored.

**Conversation-aware smoke (TOOL-06), advisory, spends tokens.** One live
two-turn exchange through `run_agent_outcome` with the corpus searcher:
turn 1 a real question, turn 2 the literal follow-up `«а в неделях?»`.
Report `pass` when the second turn's recorded `search_documents` query
contains a token from the first question's text, else `fail`. This is the
**one place in the whole gate set that spends inference tokens** — say so
in the script's own output and in README Tests (T10's job to write the
README sentence; you just need the script's behavior to match).

**The rerank mode must actually run — proved by the result contract, not
a log or a count.** Read RET-07's three flags off each answerable item's
`hybrid+rerank` `SearchResult`. The run **exits 2** unless **every one of
the ten answerable items** has `rerank_attempted is True` **and**
`rerank_succeeded is True` — name the failing items and their
`rerank_failure` strings in the exit message. Counting `llm_calls` rows or
scraping the warning log is **not** an acceptable substitute (a malformed
reply or a bookkeeping failure produces a row with no applied rerank).
Failure to construct/call the chat model at all is **also** exit 2 (an
environment failure, not a below-floor score). **Exit 0 and rerank
reported `n/a` are mutually exclusive** — never let both happen.

**The freeze.** Record `sha256` of every file under `evals/rag/corpus/`
and of `questions.json` **before the first live run**, print/report both,
and **never change either in response to a result afterward** — a
below-floor score is fixed by changing retrieval code or config only, not
the corpus or questions. `T-V190-EVAL-04` (offline, run first) is exactly
what catches a corpus defect before that freeze matters.

**Exit codes, the only three**: `0` — `hybrid` recall@5 ≥ **0.8** on the
answerable items **and** every answerable item's rerank flags are both
`True`. `1` — `hybrid` recall@5 below 0.8 (a real retrieval regression;
repairable within this task's own repair budget on retrieval code/config).
`2` — an environment failure: embeddings endpoint or corpus unavailable,
chat model impossible to construct/call, or any answerable item's rerank
flags not both `True` (this is the blocked-run condition, not a repair
cycle, if the box itself is unreachable — but IS a repair cycle if it's
your own retrieval/rerank code that's broken while the box is fine; use
judgement and disclose which in your report).

Output: a Markdown table (question × mode → `hit@r`/`miss`) then a summary
block (recall@5, MRR, page hit-rate per mode) to stdout.
`T-V190-EVAL-02` drives the whole script **offline** with `FakeEmbedder`
and `FakeLLM`, asserting the metric arithmetic on a scripted ranking —
write and pass this before attempting anything live.
