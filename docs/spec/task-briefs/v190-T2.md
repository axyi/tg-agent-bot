## `llm/embeddings.py` (REQ-V190-RET-01), exact contract

`EmbeddingsClient(base_url: str, model: str, dim: int, timeout_s: float,
client: httpx.Client)`, method `embed(texts: Sequence[str]) ->
list[list[float]]`, method `describe() -> tuple[str, str]` returning
`("lmstudio", model)`. POSTs `{"model": model, "input": [<batch>]}` to
`f"{base_url}/embeddings"` (base URL already carries `/v1`, same pattern as
`llm/lmstudio.py:65`), batches of **32** texts, `timeout=timeout_s` per
request, through the injected `httpx.Client` (transport pattern at
`llm/base.py:365-375`).

Error handling, exact:

- HTTP ≠ 200 → `EmbeddingError("embeddings http <code>")`.
- Not JSON, no `data` key, or `len(data) != len(batch)` →
  `EmbeddingError("embeddings malformed response")`.
- Entries ordered by their `index` field (do not assume response order).
- A vector whose length ≠ `dim` → `EmbeddingError("embeddings dimension
  <n> != <dim>")`.
- **One retry** on `httpx.TransportError` (this includes
  `httpx.TimeoutException`); on final failure from a `TimeoutException`,
  raise `EmbeddingTimeoutError("embeddings transport error: <class name>")
  from exc` (a distinct subclass of `EmbeddingError`, so callers can
  `except EmbeddingTimeoutError` before the parent — needed by T7's error
  matrix row 10b, which must fire before row 6's plain `EmbeddingError`).
  Any other transport failure after the retry stays a plain
  `EmbeddingError("embeddings transport error: <class name>")`. No retry on
  any non-transport failure (HTTP status, malformed body, dimension
  mismatch).

`EmbeddingError` subclasses `Exception`, **not** `LLMError`.
`EmbeddingTimeoutError` subclasses `EmbeddingError`.

Tracing: one CLIENT span per request, `tracing.start_span`, name
`f"embeddings {model}"`, attributes `gen_ai.operation.name="embeddings"`,
`gen_ai.provider.name`, `gen_ai.request.model`,
`tg_agent.embeddings.batch_size`, `tg_agent.embeddings.dim` — the two
`tg_agent.*` keys must be **registered in `_TG_AGENT_ATTRIBUTE_KEYS`**
(`tracing.py:65-84`; an unregistered key raises `ValueError` at `:211`).
`conv_id=None` when indexing, the turn's `conv_id` when querying (the
caller passes it through — T2 just needs the span to accept it).
Embeddings calls are **never** recorded in `llm_calls` (chat-shaped
columns don't fit them).

`bot.py` constructs one `EmbeddingsClient` at startup from `cfg` when
`cfg.rag_enabled`, passed as `embedder=` into `poll_loop` →
`process_update` — **this wiring is T7's job**, not T2's; T2 only needs
the class to exist and be constructible/importable, with
`embedder=None`-default call sites elsewhere staying byte-unchanged
(REQ-V190-EC-05).
