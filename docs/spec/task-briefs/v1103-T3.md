## The grammar — implement exactly, do not paraphrase

A **task section**: a line matching `^## T(\d+)\b`, body extends to the
next `^## ` line or EOF. `## The stop route …` is NOT a task section
(no digit after `T`... actually it has no `T\d` pattern at all, verify
your regex doesn't false-match on any other `## ` heading that happens
to contain "T" followed by non-digits).

A section is **exempt** when its heading matches `^## T\d+ — not
reached: .+$` — exempt sections need no candidate bullet at all.

**Only lines matching `^- T\d+ \| `** inside a non-exempt section's body
are delegation-record candidates. Every other bullet (`- result: green`,
findings, gate-table rows, anything else starting with `-`) is ignored.

Every non-exempt section MUST contain **at least one** candidate. Every
candidate MUST satisfy: stripped of its leading `- ` and split on
` | ` (literal, space-pipe-space), it yields **exactly 5 cells**:

- **cell 1** — equals the section's `T<n>` exactly (the section–task
  equality check: a candidate under `## T3` naming `T2` is invalid).
- **cell 2** — exactly `delegated: yes` or `delegated: no` (nothing
  else — `Delegated: Yes`, `delegated:yes`, `delegated: maybe` are all
  invalid).
- **cell 3** — matches `^to: \S.*$` (non-empty after `to: `).
- **cell 4** — **depends on cell 2**:
  - `delegated: no` → must be exactly `brief: —` (em dash, U+2014).
  - `delegated: yes` → must match `^brief: docs/spec/task-briefs/
    <prefix>-T<n>\.md$` where `<n>` is the SAME task number as the
    section (cell 1) — a brief naming a different task number is
    invalid ("brief names T<m>"). `<prefix>` is **derived from
    `report_path`, never hard-coded**: parse the report's basename with
    `^report-v(\d+)\.(\d+)\.(\d+)\.md$` and join the three digit groups
    — `report-v1.10.3.md` → `v1103`, `report-v1.10.4.md` → `v1104`,
    `report-v1.9.5.md` → `v195`. A basename that doesn't match that
    pattern is the problem `cannot derive a brief prefix from
    <basename>` (stop checking that report entirely, return just this
    one problem — do not also report per-section failures once the
    prefix can't be derived).
- **cell 5** — matches `^map vs actual: \S.*$` (non-empty after `map vs
  actual: `).

When cell 2 is `delegated: no`, **cell 3** must additionally contain
(substring match is fine — "contain", not "equal") one of these four
phrases **verbatim**: `commands only`, `artefacts only`, `a single edit
under every threshold`, `the task is itself the clean-context review`.
A `delegated: no` bullet whose cell 3 lacks all four phrases is invalid.

A section may carry **several** candidates (a task with two delegated
sub-parts, e.g. this release's own T6 and T7 sections will have two
each) — validate every one independently. A candidate line appearing
**before** the first `## T<n>` heading, or under a non-task section like
`## Operator inputs`, is ignored (not an error, not counted).

## Failure texts — exact strings, `<report>: ` prefixed (same style as
the ledger check's `f"{report_path.name}: ..."`)

- `T<n> has no delegation-record bullet` — non-exempt section, zero
  candidates.
- `T<n>: bullet has <k> cells, expected 5` — wrong cell count after
  splitting on ` | `.
- `T<n>: delegated: no without a §5.1 exemption phrase` — cell 2 is
  `delegated: no`, cell 3 lacks all four phrases.
- `T<n>: bullet names T<m>` — cell 1 (after stripping `- `) doesn't
  equal the section's own `T<n>`.
- `T<n>: cell 2 is neither delegated: yes nor delegated: no`
- `T<n>: cell 3 is empty`
- `T<n>: cell 4 is neither brief: — nor a <prefix> task-brief path` —
  `<prefix>` interpolated (`v1103` for this release).
- `T<n>: brief names T<m>` — cell 4's brief path names a task number
  different from the section's.
- `T<n>: cell 5 is empty`
- `T<n>: delegated: yes without a brief path` — cell 2 is
  `delegated: yes`, cell 4 is `brief: —` instead of a path.
- `T<n>: delegated: no with a brief path` — cell 2 is `delegated: no`,
  cell 4 is a path instead of `brief: —`.
- `no ## T<n> section found` — the whole report has zero task sections.
- `cannot derive a brief prefix from <basename>` — see above.
- Missing report file — reuse the existing `_lint_report_ledger`-style
  text (`f"{report_path.name}: report file does not exist"`), don't
  invent a new one.

Work out the exact validation order per candidate yourself (cell count
first, obviously, since you can't index missing cells; beyond that use
your judgement — the spec lists these as a set of checks, not a
sequence, so any order that produces the single most-specific
applicable message is fine).
