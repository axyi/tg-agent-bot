## `get_file` / `download_file` (REQ-V190-CMD-02), exact clause order

`TelegramClient` (`bot.py:97-197`) gains:

- `get_file(file_id: str) -> dict` — `self.call("getFile", {"file_id":
  file_id}, read_timeout=DEFAULT_READ_TIMEOUT_S)`, unwrapped `result` with
  `file_path`.
- `download_file(file_path: str, *, max_bytes: int) -> bytes` — `httpx`
  **GET** streamed: `self._client.stream("GET",
  f"{TELEGRAM_API_HOST}/file/bot{self._token}/{file_path}",
  timeout=httpx.Timeout(connect=10.0, read=60.0, write=10.0, pool=10.0))`,
  consume `iter_bytes()` into a buffer, raise `DocumentTooLarge` the
  **moment** the buffer would exceed `max_bytes` (close the response,
  read nothing more).

**Clause order is normative** — `httpx.TimeoutException` subclasses
`httpx.TransportError`, so a single `except TransportError` would swallow
timeouts. Define `TelegramDownloadTimeout(TelegramError)` beside
`TelegramError`; `download_file`'s handlers, in this exact order:

```python
except httpx.TimeoutException as exc:
    raise TelegramDownloadTimeout("download timed out") from exc
except httpx.TransportError as exc:
    raise TelegramError(...) from exc
```

Timeout clause first. A non-200 or other `TransportError` → plain
`TelegramError` (ERR-01 row 11); the handler must catch
`TelegramDownloadTimeout` **before** `TelegramError` (row 10a, matched by
type, never by message text). Both messages `redact()`-ed as `call` does;
the URL (carries the token) is never logged. Test this through the
**real** `download_file` boundary with an `httpx.MockTransport` raising
`httpx.ReadTimeout` — not a handler monkeypatch (`T-V190-CMD-10`).

## Before the download (REQ-V190-CMD-03), exact order

`_handle_document`'s **first action**: `started_at = monotonic()` — before
everything below (this is what DOC-04's budget check reads). Then, in
order:

1. `document.file_size` present and > **10,485,760** → "too large (file)",
   **no `getFile` call**.
2. `clean_filename(document.file_name)` (T3) `None` → "unsupported".
3. `classify(<the cleaned filename from step 2>)` (T3) `None` →
   "unsupported". **Order matters**: `classify` must run on the
   already-cleaned name, not the raw `document.file_name` — T3 found that
   a raw name with e.g. a trailing space classifies as `None` even for a
   valid extension (`"report.pdf "` → unsupported) while the cleaned name
   classifies correctly (`clean_filename` strips trailing whitespace
   first). Verify this with a test using a filename that only classifies
   correctly after cleaning.
4. **20-document limit**: one scoped `document_count(conn,
   user_id=from_id)` (T1) plus `document_id_for(conn, user_id=from_id,
   filename=<cleaned>)` (T1) to distinguish a replace from a new upload;
   at 20 and not a replace → ERR-01 row 13's line, **plain reply, no
   status message, no `getFile`**.
5. Only then: `"📄 received"` status message (CMD-04), `get_file` →
   `download_file(file_path, max_bytes=10_485_760)` — an over-cap stream
   is the same "too large (file)" line.

All five refusals happen **before any byte downloaded and before the
status message exists** (ERR-01's "rows 1, 5a-pre, 13, 14 → plain reply").
This pre-check is advisory against a race — DOC-04's transactional
recheck (already implemented, T4) is authoritative. `mime_type` ignored.
Bytes parsed from memory, never written (SEC-04 — no `open(`, no `Path(`,
no `tempfile`, no `write_bytes` anywhere in `documents.py` or this
handler; `T-V190-SEC-04` greps both via `inspect.getsource`).

## Progress, typing indicator, the two endings (REQ-V190-CMD-04)

`_StatusMessage` (`bot.py:261-328`) gains `update(text: str) -> bool`: no
message yet → send `text` as first message (record `message_id`, same
`_start` discipline as `:307-317` but with `text` not `STATUS_WORKING`);
otherwise `_edit` (`:319-323`). Returns `True` iff the message exists and
the call didn't fail. Start a `_TypingIndicator(tg, chat_id,
ceiling_s=300.0)` (`:335-406`) for indexing's duration, stop it on every
path (`try`/`except`-re-raise discipline of `:804-827`).

**Four strings, exactly, one owner each**: `"📄 received"` — handler's,
after CMD-03's five pre-checks, before `getFile`. `"📄 extracted: P pages,
N chars"` (or `"📄 extracted: N chars"` non-PDF), `"📄 chunked: N"`,
`"📄 embedding: i/n"` — all three emitted by `index_document` (T4) through
its `progress` callback, which **you** bind to `_StatusMessage.update`. No
classify string, no store string — do not invent one. On success:
`finish(ok=True)` (message **deleted**, `:284-289` semantics) then **one**
confirmation reply via `_send`: `"✅ <filename>: N chunks, P pages. Ask me
about it."` (`, P pages` only for PDFs). On failure: status message
**edited** to the ERR-01 user-facing line and **kept**; if `update`
returns `False` (no message / status disabled), send the same line via
`_send` instead — exactly one error message to the user either way. Fixed
strings stay English.
