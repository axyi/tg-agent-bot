## The bug

`storage.init_schema(conn, *, embedding_dim=None, embedding_model="")`
(`storage.py:491-521`) only creates `vec_chunks` and writes the
`rag.embedding` state key when `embedding_dim` is passed
(`_apply_embedding_pair`, `storage.py:546-563` — `None` is the documented
RAG-off no-op, REQ-V190-EC-05). All three call sites in `bot.py` call it
bare, even though a real pair is available one line earlier:

- `bot.py:2010` — `main()`, `cfg = load_config()` at `:2000`
- `bot.py:1686` — `run_selftest`, its own hardcoded placeholder `Config` at
  `:1670-1682` (never sets `embedding_dim`/`embedding_model` — stays `None`
  either way, so wiring this site is a no-op today; wire it anyway so the
  three sites cannot drift apart, per the AC)
- `bot.py:1807` — `_live_db`, `cfg = load_config()` (real pair) inside
  `run_selftest_live`

## Design — the choices are made here

- One shared helper, placed near `main()`:
  ```python
  def _init_startup_schema(conn: sqlite3.Connection, cfg: Config) -> None:
      storage.init_schema(conn, embedding_dim=cfg.embedding_dim, embedding_model=cfg.embedding_model)
  ```
  All three call sites call this, never `storage.init_schema` directly —
  that is what makes them unable to drift apart again (AC bullet 4).
- `main()` (`bot.py:2010`): replace the bare call with
  `_init_startup_schema(conn, cfg)` wrapped in
  `try: ... except ConfigError as exc: ...` — copy the existing sibling
  pattern verbatim from `bot.py:2023-2032` (`_startup_docker_wiring`'s own
  `ConfigError` catch, six lines below): `log.error("configuration error:
  %s", redact(str(exc)))  # noqa: TRY400`, close what's open so far
  (`conn.close()` only — `client`/`tg` don't exist yet at this point), then
  `return 2`. This is what makes `_bind_new_embedding_pair`'s and
  `_rebind_embedding_pair`'s `ConfigError` (orphaned `vec_chunks`, or the
  pair changed while documents exist) reachable from `main()` for the first
  time — same exit-2-with-message shape as every other config refusal, not
  a new behaviour class.
- `run_selftest` (`bot.py:1686`) and `_live_db` (`bot.py:1807`): swap the
  bare call for `_init_startup_schema(conn, cfg)`, no new exception
  handling needed — `run_selftest`'s cfg never has a real pair (confirmed:
  its `Config(...)` construction at `:1670` omits `embedding_dim`, so
  gate 4 stays exactly as offline as it is today, no sqlite-vec extension
  load on that path); `_live_db`'s existing `except Exception as exc:
  return _live_fail("db", exc)` (`:1811-1812`) already turns a `ConfigError`
  from a rebind refusal into a normal `live: FAIL db — ...` line — that's
  already the right behaviour for gate 5, don't add a narrower catch there.
