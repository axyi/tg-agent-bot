## Part B — RT-02/RT-03: `_safe_field`, `tool_call_log`, the `CASE`/`TOOLS` lines (§4)

### B1. `_safe_field` — the one sanitization helper

Add near the top of `devtools/agent_eval.py` (needs `import unicodedata`,
not yet imported — add it alphabetically with the other stdlib imports):

```python
_CONTROL_CATEGORIES = frozenset({"Cc", "Cf", "Zl", "Zp"})


def _safe_field(text: str, limit: int) -> str:
    """The only rendering path for a tool argument or a reply preview:
    redact first, then flatten every control/format/line-separator or
    whitespace character to a space, collapse runs of spaces, strip, and
    truncate. Guarantees the result is one line with no registered secret
    and no character that could forge a second stdout line."""
    redacted = config.redact(text)
    flattened = "".join(
        " " if (unicodedata.category(ch) in _CONTROL_CATEGORIES or ch.isspace()) else ch
        for ch in redacted
    )
    return " ".join(flattened.split())[:limit]
```

(`" ".join(flattened.split())` collapses consecutive spaces to one AND
strips leading/trailing whitespace in one step, since `str.split()` with
no argument already does both.)

Verify empirically: `_safe_field("\x1b[31mA\x1b[0m", 80)` → `"[31mA[0m"`
(the ESC bytes vanish, the printable bracket/digit text stays); a BEL
(`\x07`), NUL (`\x00`), U+2028, U+2029 each vanish into a single space
too; `_safe_field("a\r\nTOOLS fake", 80)` → `"a TOOLS fake"` (one line,
`\r` and `\n` each become a space, collapsed to one).

### B2. `_record_tool` fills both lists

Currently (search `_run_level2_cases`):

```python
tool_calls: list[str] = []

def _record_tool(name: str, _arg: str, *, _calls: list[str] = tool_calls) -> None:
    _calls.append(name)
```

Change to:

```python
tool_calls: list[str] = []
tool_call_log: list[str] = []

def _record_tool(
    name: str,
    _arg: str,
    *,
    _calls: list[str] = tool_calls,
    _log: list[str] = tool_call_log,
) -> None:
    _calls.append(name)
    shown = name if name in _TOOL_CALL_NAMES else "other"
    arg_text = _arg if isinstance(_arg, str) else ""
    safe = _safe_field(arg_text, 80)
    _log.append(f"{shown}({json.dumps(safe, ensure_ascii=False)})")
```

`tool_calls` keeps recording raw names (unchanged — `check_step`/every
checker still reads it unchanged). `tool_call_log` is the new parallel
list: one entry per call, `name(<JSON string>)` (the sanitized 80-char
argument, JSON-encoded — quotes/backslashes escaped by `json.dumps`, so an
argument can never inject `)`, `, ` or a second entry). Both lists grow
across the whole case (every step), never reset until the next case.

### B3. `_tools_line` and the derived cap

```python
TOOLS_LINE_CAP = 2300  # derived (RT-03): 12 calls/step (TOOL_EXECUTION_LIMIT,
# agent.py:46) x up to 182 chars/entry (17-char "search_documents(" prefix +
# 162-char worst-case JSON-escaped 80-char argument + 1-char ")" + 2-char
# ", " separator) = 2184, plus a <=40-char "TOOLS <case_id> <step> -- "
# prefix = 2224, comfortably under 2300 -- truncation is a safety net that
# cannot fire in practice.


def _tools_line(case_id: str, step_index: int, entries: list[str], cap: int = TOOLS_LINE_CAP) -> str:
    payload = ", ".join(entries) if entries else "none"
    line = f"TOOLS {case_id} {step_index} -- {payload}"
    if len(line) > cap:
        line = line[: cap - 12] + " … truncated"
    return line
```

### B4. The `CASE` line and the step cursor, inside `_run_level2_cases`

Right now the per-step loop (inside the `for case in cases:` /  `for
step_index, step in enumerate(...)` loops) does, for the two places that
currently know a step's pass/fail (the `outcome.kind in ("empty",
"no_answer")` branch, and the `check_step`/`check_memory_reset` branch):
builds a `FAIL ...` string and appends it to `fail_lines[category]` only
on failure. You need to:

1. Capture `cursor = len(tool_call_log)` **before** calling `_one_turn`
   for this step (so the TOOLS line for this step only shows calls made
   *during* this step, never an earlier step's — this is what lets a
   two-step injection case show each step's own call only).
2. After a checked step's pass/fail is known (both the outcome-kind
   branch — treat `detail = f"outcome:{outcome.kind}"`, `passed = False`
   — and the checker branch), if `record_tool_calls` is true:
   - `verdict = "PASS" if passed else "FAIL"`
   - `preview = _safe_field(reply, 200)`
   - `p(f"CASE {case_id} {step_index} -- {verdict} -- {'ok' if passed else detail} -- reply: {preview}")`
   - if `category == "injection"`: immediately after,
     `p(_tools_line(case_id, step_index, tool_call_log[cursor:]))`
3. The **legacy** `FAIL {case_id} {step_index} -- {detail} -- reply:
   {preview}` line (built with `config.redact(reply)[:200]` today) still
   only gets built and appended to `fail_lines[category]` **on failure**,
   unchanged in field order and wording, still deferred to `_run()`'s
   summary loop (`for line in fail_lines[category]: p(line)`) — the **only**
   change to it is that its `preview` now comes from `_safe_field(reply,
   200)` instead of `config.redact(reply)[:200]` (same for the
   outcome-kind branch's FAIL line).
4. `CASE`/`TOOLS` print **immediately**, in run order, interleaved with
   the case loop — never deferred. Do not print them when
   `record_tool_calls` is false (then `on_tool` stays `None` exactly as
   today, and neither line exists at all). No `CASE`/`TOOLS` line for a
   step with no `expect` (the `reset`/"nothing checked" `continue`
   branches stay exactly as they are — untouched).

Do not change `_run_level2_cases`'s or `_run()`'s call signature or
return shape (`(pass_count, fail_lines)`), `check_step`'s dispatch, or
anything about how `fail_lines` is consumed downstream.
