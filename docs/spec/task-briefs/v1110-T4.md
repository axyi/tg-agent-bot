## REQ-V1110-CBQ-01 — the plumbing and the guards

`get_updates` sends `{"timeout": LONG_POLL_TIMEOUT_S, "allowed_updates":
["message", "callback_query"]}`. `process_update` gains a `callback_query`
branch **before** the message-only guard: when `update["callback_query"]`
is a dict, hand it to `_handle_callback(...)` and return. The branch
applies the **same guards in the same order as messages**:
`callback_query.message.chat` must be a `private` chat with an int id;
`callback_query.from` must be human (`is_bot` false); `from.id in
cfg.allowed_tg_ids` — **an intruder's callback is answered with
`answer_callback_query(callback_query_id)` carrying no `text`, and nothing
else happens**: no extra log line beyond the existing `unauthorized update
from tg_id=%s` warning, no LLM call, no second Telegram call, no
application-state read/write beyond the cursor (which is written before
any of this, exactly as for messages). `message.chat.id` must equal
`from.id` (mismatch → ignored, **no answer at all** — not even the bare
ack); the rate limiter charges one token — rate-limited → acknowledged
with `text = RATE_LIMIT_REPLY` and nothing else.

## REQ-V1110-CBQ-02 — acknowledge once, first; the `callback_data` grammar

Every **handled** callback (i.e. one that passed all CBQ-01 guards) is
acknowledged with `answer_callback_query(callback_query_id)` **exactly
once, before any other Telegram call** in that handler path.
`callback_data` is ASCII, ≤64 bytes, shape `<ns>:<verb>:<arg>`, `ns ∈
{mod, ses}`. The complete verb list:

| data | meaning | arg |
|---|---|---|
| `mod:prov:<name>` | show `<name>`'s model buttons | `lmstudio` \| `openrouter` |
| `mod:model:<idx>:<h>` | select model `<idx>` of the provider currently shown | `<idx>` decimal index; `<h>` = first 8 hex digits of `sha256(json.dumps(catalogue, ensure_ascii=False, separators=(",", ":")).encode("utf-8")).hexdigest()` over that provider's catalogue of exact ids at render time |
| `mod:auto:-` | clear both overrides | literal `-` |
| `mod:back:-` | return to step 1 | literal `-` |
| `ses:switch:<id>` | **reserved, not emitted**, treated as stale | — |

`ses` is reserved so the grammar is closed — no keyboard is attached to
`/sessions` this release. **Stale/malformed** (unknown ns/verb, non-ASCII,
>64 bytes, non-integer where an integer's expected, out-of-range model
index, `mod:model` without a `<h>` segment or whose `<h>` doesn't match
the hash recomputed from the catalogue re-derived at handling time, an
unconfigured provider, a `mod:model` selection whose message no longer
shows a provider header) → acknowledged with `text = "Expired — send the
command again."` and **no state change whatsoever** (no `bot_state` write
beyond the cursor, no `set_provider` call, no edit). `callback_data` is
never interpreted as a filename/path/SQL. On `mod:model`, re-derive the
catalogue from `cfg` fresh (don't trust anything cached), recompute `<h>`,
accept the index only if `<h>` matches **and** `0 <= idx < len(catalogue)`.

## REQ-V1110-CBQ-03 — keyboards ride the table path; selection edits the
same message; the three client methods

A keyboard is `reply_markup = {"inline_keyboard": [[{"text": …,
"callback_data": …}], ...]}` attached via `send_pre(..., reply_markup=…)`
— one button per row unless MOD-01 says otherwise (MOD-01's provider row
is multiple buttons in **one** row). After a selection, the **same**
message is edited via `edit_pre(tg, chat_id, message_id, body,
reply_markup=None)` — new `<pre>` body, keyboard removed (omit
`reply_markup`) or replaced — **never** a second message. Add exactly one
new `TelegramClient` method (the other two already exist from T1):
`answer_callback_query(callback_query_id, *, text=None) ->
answerCallbackQuery` with `text` only when given, through
`_call_with_retry` like the others. `send_message`, `edit_message_text`,
`delete_message`, `get_file` stay byte-unchanged; `download_file` is
untouched this task (T5's `should_stop`).

## REQ-V1110-MOD-02 — step 2: model buttons; selection sets two keys; `auto` clears both

On `mod:prov:<name>`, edit the same message (via `edit_pre`) to `<pre>`
body `Models for <name>:` + the catalogue (MOD-04) one per line as `<idx>.
<display>` where `<display> = model_display(model_id, limit=64)`, plus
one button per model (button text = `model_display(model_id, limit=32)` —
**never the raw id**, since `reply_markup` bypasses `_pre_text`'s
escaping/redaction — call `model_display` yourself for button text), data
`mod:model:<idx>:<h>`, plus a last row `← back` (`mod:back:-`).
**Invariant**: catalogue ≤20 entries, every `model_display` form is one
line (no newline/control char survives) so with ≤20 rows of ≤64 units the
body never exceeds 4096 units and `_pre_text`'s fit never drops a row —
rendered rows ↔ emitted buttons stay strictly one-to-one.

**State lives in the message text, not the server**: the handler parses
`Models for <name>:` back out of `callback_query.message.text` (what
Telegram echoes back in the callback payload) to know which provider's
catalogue applies, re-derives the catalogue from `cfg` fresh, recomputes
`<h>`, accepts the index only if `<h>` matches and `0 <= idx <
len(catalogue)`. A missing/unparsable header, unconfigured provider, hash
mismatch, or out-of-range index is stale (CBQ-02's rule).

On a valid `mod:model:<idx>:<h>`: `storage.set_state(conn,
PROVIDER_OVERRIDE_KEY, name)` **and** `storage.set_state(conn,
f"model_override:{name}", model)`, then `set_provider(name)`, then edit
the message to `Provider: <name>, model: <model_display(model)>` (never
the raw id) with the keyboard removed.

`mod:auto:-` **and** the text form `/model auto`: delete
`provider_override` **and every `model_override:*` row** — new
`storage.delete_state_prefix(conn, prefix)` helper doing `DELETE FROM
bot_state WHERE key LIKE ?` with `prefix + '%'` — call
`set_provider(None)`, and edit (button path) or reply (text path)
`Provider override cleared.` (the existing string, unchanged). `mod:back:-`
edits back to step 1's body and keyboard (re-render MOD-01's block fresh).

## REQ-V1110-MOD-04 — the catalogue is an env allowlist

`config.py` gains `lmstudio_models: tuple[str, ...]` and
`openrouter_models: tuple[str, ...]`: the comma-separated `LMSTUDIO_MODELS`
/ `OPENROUTER_MODELS` env vars, each entry stripped, empty entries
dropped, **the configured default model always first even when the list
omits it**, then the list in env order, deduplicated (first occurrence
wins). Unset/empty → the one-entry tuple `(default,)` (so an unchanged
`.env` yields a one-entry catalogue); an empty default → an empty
catalogue.

**`model_display(model_id: str, *, limit: int) -> str`** — one helper in
`bot.py`, used everywhere a model id is shown: `redact(model_id)` first,
then every Unicode `Cc`/`Cf` character (`unicodedata.category`) replaced
by a space, whitespace collapsed (`" ".join(s.split())`), then UTF-16-safe
truncation to `limit` (OUT-03's way: never inside a scalar, one unit
reserved for `…`). Surfaces: catalogue rows ≤64 units, buttons ≤32 units,
the selection body's and the text form's `model:` value at 64. **Exact
ids are used only for**: catalogue validation (MOD-03), hashing (CBQ-02),
storage (`model_override:*`'s value), client construction (MOD-05) — never
surfaced raw anywhere a human reads it.

**`config.MODEL_CATALOGUE_MAX = 20`**: entries beyond the 20th dropped at
config load with **one** warning naming the count dropped, never the ids
— `log.warning("%s: %d model entries beyond %d dropped", name, n, 20)`.
Because the default is inserted first it's always within the 20. No live
enumeration (NG-01 — never call a live `/v1/models` endpoint).

`.env.example` gains `LMSTUDIO_MODELS=` and `OPENROUTER_MODELS=` right
after their singular counterparts (`:13`, `:18`), each with a one-line
comment. README's `## Switch provider` section gains a short paragraph
naming both vars, their semantics (comma-separated, default always
included, env order, duplicates dropped, ≤20 entries else warning-and-drop)
and the `/model <provider> <model>` text form. Do **not** touch the
`README.md:75-91`-ish output-windows/history/pricing table — unrelated.
