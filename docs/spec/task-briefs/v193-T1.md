## Commit B — prompt 174 `fix: mutation runner restores a leftover mutated tree on start-up; gate timeouts terminate before they kill`

### The defect, precisely

`devtools/checks.py:1098-1110` runs every gate with `subprocess.run(argv,
timeout=…)`. On `TimeoutExpired` Python SIGKILLs the **direct child** —
which for gate 6 is `uv`, not `mutation_check.py`. The runner is orphaned,
never signalled (its SIGINT/SIGTERM handlers at `:1545-1557` never fire),
its in-memory `_Restorer` snapshots (`:1327-1345`) die with it, and the
mutated source file stays on disk with no survivor id printed. Disclosed in
`docs/reports/report-v1.9.2.md` as a v1.10.0 item; the operator pulled it
into v1.9.3.

### Fix 1 — restore on start-up (primary; survives any kill)

Before the first mutation, `mutation_check.py` checks every distinct
`mutation["path"]` against the committed blob (`git show HEAD:<path>`,
`cwd=REPO_ROOT`, the same source of truth the repo's own drift recipe
uses). Any path whose working-tree bytes differ from `HEAD` is **reported
by name and the run refuses to start (exit 1)** — it does *not* silently
overwrite: an operator's uncommitted edit and a leftover mutation are
indistinguishable by bytes, and clobbering real work is worse than a red
gate. The message says what to do (`git diff <path>`; if it is a leftover
mutation, `git checkout -- <path>`). Skip this check when `--list`.

Corner: the runner's own test suite runs it in-process with a fake root
(`tests/test_mutation_check.py`) — the check takes the root as a parameter
and the tests either pass a root with a real `git` repo or monkeypatch the
blob reader; read how `run_all` is already tested and follow it.

Mutation entry `v193-mutation-dirty-tree-unchecked` (remove the check) with
a unit test that kills it: plant a byte difference in one mutation path
under a temp git repo (or a faked blob reader) and assert the run refuses
with that path named and `run_one` never called.

### Fix 2 — SIGTERM before SIGKILL in the gate runner (complementary)

`devtools/checks.py` `_run_command` (or whatever the function at `:1098`
is named): replace `subprocess.run(timeout=)` with `Popen(…,
start_new_session=True)` + `communicate(timeout=)`; on `TimeoutExpired`
send `SIGTERM` to the **process group** (`os.killpg(proc.pid, SIGTERM)`),
wait a grace (`_TERMINATE_GRACE_S = 5.0`, module constant, commented), then
`SIGKILL` the group, then `communicate()` to reap. Result semantics
unchanged (`CommandResult(False, None, …, "timed out after …s")`). Every
gate benefits; for gate 6 it means `mutation_check.py` gets the SIGTERM its
handler already restores on.

Then make the runner's handler complete: `_install_signal_handlers`'s
`_handler` restores the tree but leaves the `pytest` child running. Track
the current `subprocess.Popen` (the runner currently uses
`subprocess.run` at `:1541`) and terminate its process group before
`sys.exit(1)`. Test: existing signal-handler tests in
`tests/test_mutation_check.py` (find them) extended for "child terminated".

Test for Fix 2: `tests/test_v15_standards.py` has a timeout test
(`test_v15_scan_03_fail_closed_timeout`, 1.06 s) — extend or add one that
runs a child which traps SIGTERM and writes a marker file before exiting,
asserting the marker exists after the timeout path (proves SIGTERM was
delivered, not only SIGKILL). Keep it under 2 s.
