## Commit B — prompt 178 `fix: ruff bug-class tier (PLW1510, TRY400, ISC004, RUF005/007, PERF401, SIM105/117, TRY004, PLW2901)`

Each hit read by hand; the report carries one line per **rule** with the
count fixed/dismissed and, for the three rules below, one line per **site**:

- **`PLW1510` (17) — `subprocess.run` without `check=`.** The dangerous
  fix is `check=True` on a call whose non-zero exit is expected and handled
  via `returncode` (`devtools/checks.py`'s gate runner, `mutation_check.py`'s
  test runner, `tools.py` exec/docker paths are exactly that). For every
  site: if the code reads `.returncode` afterwards → `check=False`,
  explicit; if a non-zero exit is a bug today → `check=True` **and** a
  test that the exception surfaces. One line per site in the report.
- **`TRY400` (16) — `log.error` inside `except`.** `log.exception` adds
  the traceback; that is a log-output change. Adopt it where the except
  block is a genuine unexpected-error path; keep `log.error` (with
  `# noqa: TRY400 -- <why>`) where the exception is an expected, already
  classified failure whose traceback would be noise (the LLM `LLMError`
  paths, the bot's per-update guard). Tests that assert on log records
  (`caplog`) may pin `levelname`/message — repoint, never delete.
- **`ISC004` (32) — implicit string concatenation inside a collection
  literal.** This is the missing-comma bug class. Read all 32: a
  deliberately wrapped long string stays and is made explicit (`+` or a
  parenthesised single literal); a missing comma is a real bug — fix it and
  add a test that would have caught it. Report each of the 32 as
  `intentional` or `bug`.
- `RUF005`, `RUF007`, `PERF401`, `SIM105`, `SIM117`, `TRY004`, `PLW2901`:
  mechanical rewrites; `SIM105` (`contextlib.suppress`) and `SIM117`
  (merged `with`) must not change which exceptions are swallowed or the
  order of context-manager exit — read each.
- Then add the rules to `select`; `ruff check .` exit 0.
