## `documents.classify` / `documents.clean_filename` (DOC-01)

`classify(filename: str) -> str | None` — lowercase extension only
(`Report.PDF` → `"pdf"`), one of `"txt"`, `"md"`, `"docx"`, `"pdf"`, else
`None`. Never consult MIME type, magic bytes or Telegram's `mime_type`.

`clean_filename(raw: str | None) -> str | None` — `None`/empty → `None`;
strip path separators (`/`, `\`) and every control character (`ord < 32`,
`0x7f`); strip whitespace; cut to **120** characters; empty result →
`None`. This one value becomes `documents.filename` (STO-02), the
`/documents` display name, the `/delete` match key and the attribution
string — one cleaning function, four downstream uses, so get it exactly
right; later tasks depend on it byte-for-byte.

## `documents.extract` (DOC-02) — exact per-type rules

`extract(data: bytes, file_type: str) -> Extracted`. Two frozen
dataclasses, defined **exactly once**: `ExtractedPage(text: str, page:
int | None)` (page = PDF's 1-based physical page number, `None` for every
other type) and `Extracted(pages: tuple[ExtractedPage, ...], page_numbered:
bool)`. No parallel `page_numbers` field, no `tuple[str, ...]` form.

- **txt/md**: decode `utf-8-sig`; on `UnicodeDecodeError` decode `cp1251`
  (stdlib codec, Russian-Windows fallback). One
  `ExtractedPage(text, page=None)`, `page_numbered=False`. No Markdown
  rendering or stripping — keep the raw text.
- **docx**: before `python-docx` is touched at all, open with
  `zipfile.ZipFile` and bound the archive: at most **2,000** members,
  aggregate uncompressed size at most **50 MiB**, no single member over
  **20 MiB**, aggregate compression ratio (uncompressed ÷ compressed) at
  most **100** — a violation refuses the document (this becomes ERR-01 row
  5b via whatever exception T4/T7 catch; for T3's own purposes, raise a
  clear, named exception documents.py owns). Then `python-docx`
  `Document(io.BytesIO(data))`; walk `document.element.body`'s children **in
  document order**, emitting paragraph text and table-cell text as they
  appear — paragraphs joined by `\n`; within a table, cells joined by `\t`
  inside a row, rows by `\n`. One `ExtractedPage(text, page=None)`,
  `page_numbered=False`. `zipfile.BadZipFile`,
  `docx.opc.exceptions.PackageNotFoundError`, `KeyError` are the
  corrupted-DOCX exception class.
- **pdf**: `pypdf.PdfReader(io.BytesIO(data))`; before any
  `extract_text()`, `len(reader.pages)` must be ≤ **500** (more refuses,
  same "too large" family as the DOCX bound above — a T3-owned named
  exception, not yet wired to ERR-01 strings, that's T4/T7's job). Then
  `page.extract_text()` per page. A page whose text is empty after
  `strip()` is **skipped entirely** — contributes no `ExtractedPage`, no
  chunk — and the pages that remain **keep the PDF's 1-based physical
  index** (never a running/renumbered count), so `page_numbered=True`.
  **Exception boundary, exact**: only exceptions from `PdfReader`, from
  page enumeration, or from `extract_text()` are the "corrupted PDF" class
  — T3 does not yet implement DOC-04's between-pages budget check (that's
  T4, which will thread `documents.IndexBudgetExceeded` through this same
  loop and must be able to let it propagate un-mapped to "corrupted"; your
  job is just to leave the per-page loop straightforward enough for T4 to
  insert that check between pages without restructuring your extraction
  logic — do not pre-emptively add a budget parameter to `extract` itself,
  DOC-04's budget check happens in `index_document`, not in `extract`).

No temporary file, no `Path`, no `open()` anywhere in `documents.py`
(`T-V190-SEC-04` greps this).

## `documents.chunk_text` (DOC-03) — the offset-based algorithm, normative

`chunk_text(text: str, *, target: int = 1000, hard_max: int = 1200,
overlap: int = 200, minimum: int = 50) -> list[Chunk]`, `Chunk` a frozen
dataclass `(text, char_start, char_end)`, offsets into the **original**
input string.

1. Split on blank lines (`\n\s*\n`) into paragraphs, keeping each
   paragraph's offsets **and the separator text between them** — a chunk's
   `text` is always the original slice `text[char_start:char_end]`; never
   invent, drop or normalise a separator.
2. **Offset-based, one walk.** A chunk is `[char_start, char_end)`. **1,200
   is the hard ceiling everywhere, before and after any merge** — no chunk
   text may ever exceed `hard_max`. After the first chunk, new material a
   chunk may take is at most `hard_max - overlap` = **1,000**, so the
   200-char overlap prefix can never push a chunk past 1,200.
3. Accumulate paragraphs while the running length stays ≤ `target`; a
   paragraph that would push it over closes the chunk. A single paragraph
   longer than the current allowance is split on sentence ends (`. ! ?`
   followed by whitespace) into pieces ≤ `target`; a sentence still longer
   than the allowance is hard-cut **at the allowance**, never at
   `hard_max`.
4. Each chunk after the first starts with the last `overlap` characters of
   the previous chunk's text (`char_start` therefore lies inside the
   previous chunk's span); rule 2's allowance keeps the running total ≤
   `hard_max`.
5. A final chunk shorter than `minimum` **non-whitespace** characters
   merges into the previous chunk **only if the merged length stays ≤
   `hard_max`**; otherwise it stands alone. A text shorter than `minimum`
   yields one chunk if it has ≥ 20 non-whitespace characters total, else
   zero chunks (an empty-text refusal — DOC-04's job to turn into an ERR-01
   string; `chunk_text` itself just returns `[]`).
6. Deterministic: same input → same output. No randomness, no clock.

For a PDF, `chunk_text` is called **once per page** by the caller
(`index_document`, T4's job) — a chunk never spans pages. T3's own
`chunk_text` takes plain `text`; it does not know about pages. `chunk_index`
(0-based, across the whole document including across pages) is assigned by
the **caller** (T4), not by `chunk_text`.

## `devtools/pdf_fixture.py` (DOC-06)

`write_pdf(pages: Sequence[str]) -> bytes` — a hand-built PDF-1.4 byte
string, one page per input string, Helvetica 12pt, **ASCII only** (a
non-ASCII char raises `ValueError`), lines split on `\n`, drawn top-down at

`(`, `)`, `\` escaped in PDF text strings, a correct `xref` table and
`trailer` so `pypdf` 6.18.0 reads every page and `extract_text()` returns
the lines. Standard library only — no import from the bot's modules, no
new dependency. Has a `main()` for operator use. `devtools/` stays never
imported by the bot — this module is imported by **tests** and by
`devtools/rag_eval.py` (T8, not yours) only.
