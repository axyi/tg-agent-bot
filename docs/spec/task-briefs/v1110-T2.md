### REQ-V1110-STA-01 — `/stats` as one `<pre>` table

`_render_stats` keeps its data sources unchanged
(`metrics.conversation_stats`, `metrics.global_stats`,
`metrics.error_breakdown`, `metrics.summary_health`, `metrics.top_tools`,
`metrics.turn_timeline` — never its own SQL) and `STATS_MAX_CHARS = 3500`,
but now returns one body for the **table path** (via `send_pre`, landed by
T1): a three-column table `metric | this conv | all time`
(`max_width` 22 / 16 / 16 = 54, plus two two-space separators = 58 ≤ 72
units) over the paired rows **in this order**: `LLM calls`, `errors`,
`tokens in`, `cached`, `reasoning`, `tokens out`, `est. cost`,
`cost basis`, `avg prompt/call`, `re-sent share` — followed by a blank
line and the four single-value lines `Top tools: …`, `Last turn: …`,
`Errors: …`, `Summaries: …` built by the unchanged helpers
(`_render_top_tools`, `_render_last_turn`, `_render_errors_line`,
`_render_summaries_line`).

**The four single-value rows are wrapped, not truncated**: a value longer
than the width remaining after its label continues on following lines
indented by two spaces, every line ≤72 UTF-16 units (this is `tables.py`'s
own rule from T1 — reuse it, do not reimplement), broken at spaces where
possible, never inside a Unicode scalar. The wrapped lines then go through
the same fit as every other line.

Cell-content semantics preserved verbatim: `n/a` for a missing value
(`_cell`), `n/a (no pricing)` for a side without a pricing basis
(`_render_cost`), `mixed` when bases disagree, the percent rendering of
`_render_share`. The title line `Stats (this conversation | all time)`
becomes the table header. `_fit` is replaced **for this command only** by
`tables.fit_lines` at the 3500-character cap (`STATS_MAX_CHARS`), whole
lines (continuation lines included) dropped from the end, `… N more`
appended — same behavior as today's `_fit`, just via the new helper. Do
not delete `_fit` if anything else still calls it — check first (T1's
`_render_document_line`/others may not use it, but confirm with a grep

### REQ-V1110-DOC-01 — `/documents` as a table

`_handle_documents` keeps `storage.list_documents` (ordered `created_at,
id`) and the empty case (`DOCUMENTS_EMPTY_REPLY`, **plain path**,
unchanged) — otherwise sends one table-path body whose **first line is
`Your documents (N of 20):`** (`20` = `documents.DOCUMENT_LIMIT`, import
it), a blank line, then `render_table` over columns `#` (`documents.id`),
`file` (filename, `redact()`-ed as today, `max_width` 24), `type`, `size`
(`size_bytes` in human units: `< 1 MB` → `NNN.N KB`, else `NN.N MB`, one
decimal, decimal units — i.e. 1 MB = 1,000,000 bytes not 1,048,576;
`0.0 KB` for zero), `chunks`, `pages` (`n/a` for non-PDF rows,
`page_count` otherwise), `added` (`created_at[:10]`). Width: `#` 3,
`file` 24, `type` 4, `size` 8, `chunks` 6, `pages` 5, `added` 10 = 60, plus
six two-space separators = **72 ≤ 72 units exactly** — get this right, it's
at the hard ceiling.

to confirm no other caller exists before deleting it).

### REQ-V1110-DOC-02 — `/delete #<id>`

`_handle_delete` keeps `REQ-V190-CMD-06`'s exact-match filename semantics.
`DELETE_USAGE_REPLY`'s text becomes `Usage: /delete <filename> | /delete
#<id>` (one literal — T0's pin inventory already names this site,
`bot.py:97`, now likely `bot.py:97` unchanged since it's near the top of
the file, unaffected by T1's insertions further down).

An argument starting with `#` is an id form: `#` followed by ASCII digits
only → `storage.delete_document(conn, user_id=from_id,
document_id=int(...))` (already ownership-scoped by its `AND d.user_id =
?` predicate — do not add a second check) → `Deleted #<id>.` on `True`;
`False` (an id the caller doesn't own, or none at all — the two cases are
**not** distinguished in the reply) → `No document named #<id>.`; `#`
followed by anything but digits → the same `No document named #<id>.`
shape (echo the raw `#...` argument, not a parsed id). A filename that
happens to start with `#` is unreachable by name after this change — note
that in the README row you touch.

### REQ-V1110-DOC-03 — the refusal wording split

`bot.py`'s exception-handling block maps `DocxArchiveTooLargeError` and
`PdfTooManyPagesError` onto `DOC_TEXT_TOO_LARGE_REPLY` today (a
2,001-page PDF wrongly told it has too many *characters*). Add two new
constants next to the existing reply constants (`bot.py:80-97` area):
`DOC_DOCX_BOUNDS_REPLY = "Document too large (DOCX archive bounds)."` and
`DOC_PDF_PAGES_REPLY = "Document too large (over 2,000 pages)."` — use
them in those two `except` clauses only (clause order and exception
classes unchanged). `DOC_TEXT_TOO_LARGE_REPLY`'s text becomes `Document
too large (over 2,000,000 characters).` — **note**: this changes the
*number* only; T5 is the task that changes the underlying
`MAX_EXTRACTED_TEXT_CHARS` constant itself (2,000,000) and `PDF_MAX_PAGES`
(2,000) — for T2, just land the three reply strings with the numbers the
spec gives (2,000,000 / 2,000 pages), even though the constants they
describe don't move to those values until T5. This looks like forward
reference but is intentional per the spec's own task split (§14 T2/T5
rows) — the strings are static text, not derived from the constants at
this point in the sequence.
