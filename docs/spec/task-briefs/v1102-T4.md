## Fix 1 — `AGENTS.md`'s gate-5 sentence still contradicts itself

the bolded clause, but left the tail sentence unreconciled):

```
Gates 1–4 are unconditional and offline (gate 3, `pytest`, is 1638
tests as of spec-v1.9.5 T2). Gate 5 needs the live environment
(a provisioned `.env`, a reachable Docker daemon with the sandbox image
pulled, every provider the configuration routes to); it spends no
inference tokens and sends no Telegram message. **Gate 5 must be fully
green at every commit, including an OpenRouter key; LM Studio only when
a route names it** — the v1.2 "record the failure and proceed" exception is
withdrawn: an unreachable LM Studio is a blocked run, not a noted one, because
the benchmark measures against it.
```

The tail — "an unreachable LM Studio is a blocked run, not a noted one,
because the benchmark measures against it" — still asserts LM Studio is
unconditionally required, contradicting the bolded clause right before it
(LM Studio only matters "when a route names it") and the benchmark-waiver
paragraph twelve lines below (the benchmark rule is *waived* this
release). Reword the tail to match the conditional posture — the
intent is: gate 5 must be green for every provider the run's
configuration actually routes to (an OpenRouter key when OpenRouter is
routed, LM Studio only when some route names it); an unreachable
*configured* provider is a blocked run, never merely noted. Something in
this shape (adjust wording to fit the surrounding sentence naturally,
keep it one sentence-flow, don't restructure the whole paragraph):

```
**Gate 5 must be fully green at every commit for every provider the
configuration routes to** — the v1.2 "record the failure and proceed"
exception is withdrawn: an unreachable *configured* provider is a
blocked run, not a noted one; a provider no route names SKIPs cleanly
instead and is not a blocker.
```

Also correct `docs/reports/report-v1.10.2.md`'s T3 section (search for
"the gate-5 sentence now names 'every provider the configuration routes
to' instead of hard-requiring LM Studio") — that sentence currently
overstates what T3 actually landed (the hard-requirement tail survived
T3 unedited); reword it to match what T3 actually did and what this
fix now completes.

Add or extend a test (in `tests/test_v1102_docs.py`, alongside the

## Fix 2 — `T-V1102-RT-08`'s duplicated fixture (missing U+2028 variants)

`tests/test_v1102_red_team.py` around line 349-357,
`test_t_v1102_rt_08_sentence_boundary_negatives_no_hal_marker_hit`'s
parametrize list currently has **four** entries but only **two distinct
strings** — the two ASCII-terminator negatives are each listed twice by
mistake:

```python
@pytest.mark.parametrize(
    "reply",
    [
        "нет ответа. Конкретной информации нет",
        "нет ответа? Конкретной информации нет",
        "нет ответа. Конкретной информации нет",
        "нет ответа? Конкретной информации нет",
    ],
)
```

The spec (§5 RT-05's worked examples, and the RT-08 row of §8.1's test
table) requires the two ASCII-terminator negatives **and** "both with
U+2028 in place of the space after the terminator" — five string
descriptions total in the spec's own text, but as fixtures here the
requirement is: the two ASCII versions (already present, just
duplicated) plus the two U+2028 versions (missing entirely). Replace the
duplicate pair with the U+2028 variants — the space immediately after
the sentence terminator (`.` or `?`) becomes U+2028, nothing else
changes:

```python
@pytest.mark.parametrize(
    "reply",
    [
        "нет ответа. Конкретной информации нет",
        "нет ответа? Конкретной информации нет",
        "нет ответа. Конкретной информации нет",
        "нет ответа? Конкретной информации нет",
    ],
)
```

Run the test after the change and confirm it's still green (the
underlying regex behavior is already correct — `\s` matches U+2028 and
the gap's token-exclusion class still refuses a terminator-bearing
token — this is purely a missing-fixture fix, no code change expected).
If it somehow goes red, stop and report rather than adjusting the regex.
