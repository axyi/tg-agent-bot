## What to build

### REQ-V1110-SES-01 — two storage helpers, derived titles, schema 6

A session **is** a `conversations` row — no new table, no new column,
`SCHEMA_VERSION` stays **6**, `_SCHEMA` byte-unchanged. `storage.py`
gains:

```
list_conversations(conn, tg_user_id: int, *, limit: int) -> list[sqlite3.Row]
```
`recent_conversations`'s column set (`id`, `created_at`, `active`,
`message_count`, `last_activity`), **filtered by `tg_user_id`**, plus a
computed `title`: the content of the conversation's first `user` message
(`messages` ordered by `id`), whitespace-collapsed
(`" ".join(content.split())`), cut to 40 characters with a trailing `…`
when longer, `(empty)` when the conversation has no user message. Compute
the title in SQL or Python, whichever is simpler given the existing
`recent_conversations` pattern — it is **never stored**. Order:
`last_activity DESC NULLS LAST, id DESC`, bounded by `limit`.

```
count_conversations(conn, tg_user_id: int) -> int
```
For the `/sessions` trailing line.

```
activate_conversation(conn, tg_user_id: int, conv_id: int) -> bool
```
Follow `start_new_conversation`'s exact transactional recipe: `BEGIN
IMMEDIATE`; `UPDATE conversations SET active = 0 WHERE tg_user_id = ? AND
active = 1`; `UPDATE conversations SET active = 1 WHERE id = ? AND
tg_user_id = ?`; when the second update's `rowcount` is 0, **roll back**
(restores the caller's previous active row) and return `False`; else
`COMMIT` and return `True`. This transactional form is mandatory — the
partial unique index (`idx_conversations_one_active`) means a naive
two-statement non-transactional version can violate it under concurrent
access, and more importantly a foreign/missing id must leave the caller's
own active row untouched, which only the rollback guarantees. A missing
or foreign id therefore changes **nothing**.

### REQ-V1110-SES-03 — `/session <id>`, and `/new` names its id

Add `/session` to the dispatch chain. Argument parsing: exactly one
argument of ASCII digits → call `activate_conversation`; `True` → **plain**
reply (not table-path) `Switched to session #<id>: <title>` (the title
computed the same way `list_conversations` derives it — redacted); `False`
→ `No session #<id>.` (never reveal whether the id belongs to someone
else — same wording for "doesn't exist" and "exists but isn't yours").
Bare `/session`, more than one argument, or a non-integer argument →
`Usage: /session <id> (see /sessions)`. Switching does **not** summarize
the outgoing conversation (NG-14 — this is deliberately different from
`/new`'s behavior) and does not write to `messages` or `summaries` — only
the `activate_conversation` transaction touches `conversations`. The
agent's next turn already picks up the newly active conversation for free
through the unchanged `get_or_create_active_conversation` +
`load_context_messages` path — you don't need to touch that.
