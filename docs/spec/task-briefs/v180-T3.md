   bounds exactly — so all four phases become callable per request. No

3. **`_TypingIndicator` class in `bot.py`**, constructor exactly:
   ```python
   _TypingIndicator(tg, chat_id, *, ceiling_s: float,
                     interval_s: float = TYPING_INTERVAL_S,
                     monotonic: Callable[[], float] = time.monotonic,
                     stop_event: threading.Event | None = None)
   ```
   `ceiling_s` has **no default** (an omission is a `TypeError`, not a
   silent forever-typing indicator). `stop_event=None` constructs a real
   `threading.Event`. A `start()` method spawns one **daemon**
   `threading.Thread` running a loop that:
   - sends immediately on start (before any wait);
   - after each send, waits on the stop event for `interval_s` (so a run
     finishing inside the interval still shows the indicator, and `stop()`
     wakes the worker instead of sleeping out the interval);
   - **checks, immediately before each attempt, in order**: the stop event
     (set → return without sending), then the elapsed clock via
     `monotonic()` against `ceiling_s` (≥ ceiling → return, no request);
   - issues **one unretried** `tg.call("sendChatAction", {"chat_id":
     chat_id, "action": "typing"}, read_timeout=TYPING_REQUEST_TIMEOUT_S,
     connect_timeout=TYPING_REQUEST_TIMEOUT_S,
     write_timeout=TYPING_REQUEST_TIMEOUT_S,
     pool_timeout=TYPING_REQUEST_TIMEOUT_S)` per tick — **never**
     `_call_with_retry`;
   - **re-checks the stop event after the request returns**, before
     scheduling anything further (the named residual: at most one stale
     action can land, ~5s after the reply, if the worker was mid-request
     when `stop()` fired — accepted, not fixed);
   - on **any** exception from `tg.call`: one `log.warning` with
     `config.redact()` applied, disable the indicator for the rest of this
     run (no retry, no second attempt), thread exits, run unaffected.
   `stop()` sets the event and joins the thread bounded by
   `TYPING_JOIN_TIMEOUT_S`; a timed-out join is logged once and `stop()`
   returns anyway (daemon thread, cannot block shutdown). `stop()` is
   idempotent (safe to call twice, safe to call if `start()` was never
   called or already stopped itself on error).
