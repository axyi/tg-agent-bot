## Goal

Add `LLM_JUDGE_MODEL`, one more routed purpose, mirroring
`llm_eval_chat_model`/`LLM_EVAL_CHAT_MODEL` exactly (same shape, same
validation, same error-text convention) — plus a `purpose="judge"` branch
in `llm.build_llm_client`, plus the `.env.example` documentation block.

## Exact changes

1. **`config.py`**: add `llm_judge_model: str = ""` immediately after
   `llm_eval_chat_model: str = ""` (`config.py:155`), with a comment in the
   same voice as the `llm_eval_chat_model` comment above it (`:150-154`) —
   but say this one is for gate 8's judge purpose, always routed to a
   separate model, never the chat model under test.

2. **`config.py`'s `load_config`**: immediately after the `eval_chat_model`
   block (`config.py:409-427`), add the identical pattern for
   `LLM_JUDGE_MODEL`:

   ```python
   judge_model = ""
   routed_judge = parse_routed_model(_value(source, "LLM_JUDGE_MODEL"), "LLM_JUDGE_MODEL")
   if routed_judge is not None:
       routed_provider, routed_name = routed_judge
       configured = (
           bool(lmstudio_base_url and lmstudio_model)
           if routed_provider == "lmstudio"
           else bool(openrouter_api_key and openrouter_model)
       )
       if not configured:
           raise ConfigError(
               f"LLM_JUDGE_MODEL routes the judge to {routed_provider}, which is not configured"
           )
       judge_model = f"{routed_provider}:{routed_name}"
   ```

   and add `llm_judge_model=judge_model,` to the `Config(...)` constructor
   call, next to `llm_eval_chat_model=eval_chat_model,` (`config.py:534`).

3. **`llm/__init__.py`'s `build_llm_client`**: add a `purpose == "judge"`
   branch **after** the existing `purpose == "eval-chat"` branch (after
   `llm/__init__.py:63`), identical in shape:

   ```python
   if purpose == "judge":
       routed = parse_routed_model(cfg.llm_judge_model, "LLM_JUDGE_MODEL")
       if routed is not None:
           provider, model = routed
           return _client_for(cfg, provider, client, model=model)
   ```

   Unset → falls through to the main client, exactly like every other
   purpose (do not add any special-case fallback logic — the runner that
   consumes this at T5 is responsible for refusing an empty
   `cfg.llm_judge_model` itself, not this factory).

4. **`.env.example`**: after the `LLM_EVAL_CHAT_MODEL` block (ends around
   `:88`, before the "Reasoning policy" section), add — **uncommented**,
   following the `LLM_RERANK_MODEL` convention (uncommented default,
   `.env.example:86`), NOT the `LLM_EVAL_CHAT_MODEL` convention (commented
   out):

   ```
   # The judge route for gate 8's LLM-as-a-judge (devtools/agent_eval.py):
   # always a separate, stronger model, never the chat model under test --
   # the runner refuses to run if this equals the chat client's route.
   LLM_JUDGE_MODEL=openrouter:openai/gpt-4.1
   ```

   Exactly one uncommented `LLM_JUDGE_MODEL=` line must exist in
   `.env.example` after this edit, reading exactly
   `LLM_JUDGE_MODEL=openrouter:openai/gpt-4.1`.
