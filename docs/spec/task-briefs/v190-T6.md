(`:1249`) — existing indices and order must not shift:

```python
{
    "type": "function",
    "function": {
        "name": "search_documents",
        "description": (
            "Search the users uploaded documents; returns the best passages with "
```

## Dispatch and the envelope (REQ-V190-TOOL-02)

`execute_tool` (`tools.py:1280-1316`) gains keyword-only `searcher:
Searcher | None = None` beside `fetcher`. `Searcher` is declared as a
`Protocol` in `tools.py` with one method, `search(query: str) ->
SearchResult`. A branch after `fetch`'s own (`:1311-1315`):

- `query` not a non-empty string ≤ 1000 chars → `{"error": "query must be
  a non-empty string of at most 1000 characters"}` through `_envelope`
  (`:1351`), same pattern as other `_refuse`-style tool errors.
- `searcher is None` → `{"error": "search_documents is not available"}`.
- Otherwise call `searcher.search(query)` and build the payload
  `{"text": <envelope>, "passages": n}`:
  - `documents_present` false → envelope text `"No documents uploaded for
    this user. Supported: .txt .md .docx .pdf"`.
  - documents exist, no passages → `"No passages matched."`.
  - otherwise: header `"Found N passages:"` then one block per passage:
    `"[n] <filename> — page <p> | chunk <i>: <text>"` (omit `"page <p> | "`
    when `page` is `NULL`), blocks separated by a blank line.

**Per-passage truncation, exact arithmetic.** `RAG_PASSAGE_CHARS = 1000` —
a **module constant in `tools.py`**, deliberately not configuration. Before
joining blocks: `len(text) > 1000` → `text[:999] + "…"` (exactly 1000
chars including the ellipsis); otherwise unchanged. The header part of a
block is **never** truncated. This must happen **per passage before the
blocks are joined** — never a blind cap on the joined text (that would
drop or bisect a block while `passages: N` still claimed it). Then
`compact_output(text, max_chars=12000)` (`tools.py:296`) — this cannot cut
a represented passage at the arithmetic bound (10 × (1000+~120) = ≤11,200
< 12,000; at default K=5, ≤5,600). Result passes `_envelope` (redacted like
every tool output). Passages are untrusted data — no new prompt rule
needed for that, `agent.py:122-123` already covers it.

## Attribution (REQ-V190-TOOL-05), the structural guarantee

`rag.attach_sources(reply: str, calls: list[SearchResult]) -> tuple[str,
bool]`, called from `bot.py` after `run_agent_outcome` returns and before
`_send` (`bot.py:805-828`), only when `outcome.failed` is false and the
turn's `Searcher` recorded ≥ 1 call (`Searcher.calls`, T5's field).

- **Passages were returned** (any call with ≥1 passage): collect distinct
  `(filename, page)` pairs across all calls, first-seen order, **at most
  5**. `rag._render_sources(pairs) -> str`: group by filename in
  first-seen filename order, each filename followed by `(page N)` for a
  single page or `(pages N, M, …)` for several in first-seen page order,
  nothing when page is `NULL`; join filenames with `, `. Canonical block:
  `"\n\nSources: " + _render_sources(<all collected pairs>)`.

  **Validation never parses a filename** — a filename may legally contain
  commas/parens/colons/the words page/pages. Instead: for **every
  non-empty subset** of the collected pairs (first-seen order, same
  grouping rule), compute `_render_sources(subset)` — at most 5 pairs ⇒ at
  most 31 subsets, computed once per turn. A reply line beginning
  `Source:`/`Sources:` survives **only** when its whole text, stripped of
  surrounding whitespace, equals `"Source: "` or `"Sources: "` followed by
  one of those renderings — exact string equality against the generated
  set, nothing extracted or matched loosely. Either prefix accepted (the
  prompt teaches the model the singular `Source:`; the bot's own appended
  block always uses `Sources:`).

  Any `Source:`/`Sources:` line matching no rendering is **removed**, with
  one `log.warning("stripped an invented source line")`. If no valid
  source line remains after that pass, append the canonical block. A
  filename mentioned in prose elsewhere does **not** satisfy attribution
  and does not suppress the block. Return `(reply, True)` whenever the
  reply changed.
- **No passage returned by any call**: strip any `Source:`/`Sources:`
  line, log the same warning, return the rest.
- **Otherwise**: reply untouched.

The appended block counts toward `split_message`'s limit (`bot.py:213`),
never past it.
