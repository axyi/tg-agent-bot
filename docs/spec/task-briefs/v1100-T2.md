## Goal

Pin two already-correct behaviours with new tests: (1) the Telegram
send-payload builder never carries `parse_mode`/`entities` and MarkdownV2
specials are delivered verbatim (OUT-02, "satisfied by design" — no escaper
exists and none should be added); (2) the tool-call wire coercion
(`llm/base.py`'s `parse_response`) feeds `tools.execute_tool`'s decode point
correctly end to end, for all four envelope shapes (TC-01).

## Where the real code already is (read, do not change)

- `bot.py:225-226` — `TelegramClient.send_message`: `self._call_with_retry("sendMessage", {"chat_id": chat_id, "text": text})`. This is the whole send-payload builder — the two keys, nothing else.
- `llm/base.py:345-374` (`parse_response`): the wire coercion for `tool_calls[].function.arguments` — `None`/missing → `""`; a JSON object → `json.dumps(raw_arguments, ensure_ascii=False)`; a string passes through; a non-dict `tool_calls` entry (`entry = raw_entry if isinstance(raw_entry, dict) else {}`) yields an empty `ToolCall` (`id=""`, `name=""`, `arguments=""`), never raises.
- `tools.py:1405-1428` (`execute_tool`'s body, shown above the line numbers may drift by a few lines — search for `parsed = json.loads(arguments)`): `json.loads` failure (`TypeError`/`ValueError`) → `_refuse(name, "arguments are not valid JSON", audit)`; a non-dict parse → `"arguments must be a JSON object"`; an unknown tool name → `_envelope({"error": f"unknown tool: {name}"})`. Never raises.
