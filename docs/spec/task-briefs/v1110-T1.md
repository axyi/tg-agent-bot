### REQ-V1110-OUT-01 — two new helpers, the table path

`bot.py` gains `send_pre(tg, chat_id, body, *, reply_markup=None) -> dict |
None` and `edit_pre(tg, chat_id, message_id, body, *, reply_markup=None) ->
dict | None`. Both call one shared `_pre_text(body) -> tuple[str, str]`
that redacts, fits to 4096 entity-parsed UTF-16 units, escapes, and wraps
exactly one `<pre>` block — returning **both** the HTML `text` and the
fitted, redacted plain body (`fitted`), so the HTML request and OUT-04's
plain fallback send the same fitted body. Command/callback handlers never
call `send_message_html`/`edit_message_html` directly — only through
`send_pre`/`edit_pre`.

Construction order, exactly this and no other:
`redacted = redact(body)`; `fitted = tables.fit_lines(redacted.splitlines(),
limit=MESSAGE_LIMIT)`; `text = "<pre>" + html.escape(fitted, quote=False) +
"</pre>"` — **redact before fit, fit before escape, escape before
wrapping**. `fit_lines` joins by `"\n"` with no trailing newline (a body's
trailing newline is dropped).

`send_pre` calls the new `TelegramClient.send_message_html(chat_id, text,
reply_markup=None)`: payload exactly `{"chat_id", "text", "parse_mode":
"HTML"}` plus `"reply_markup"` when given, nothing else — no other tag, no
MarkdownV2, no `entities`. `edit_pre` calls
`edit_message_html(chat_id, message_id, text, reply_markup=None)`
(`editMessageText`), same rule, plus `message_id`.

**The table path never splits.** Fitted over the redacted, not-yet-escaped
lines: entity-parsed length (tags don't count, an escaped `&lt;` counts as
one unit = `utf16_length` of the raw `<`) must stay ≤ 4096. Whole lines
dropped from the end, a final `… N more` line appended until it fits — the
existing `_fit` pattern (`bot.py:1190-1197` in the cited baseline — confirm
the actual location in the live tree) but over lines, never a hard slice
inside a line.

The table path is used by **`/stats`, `/documents`, `/sessions`, `/model`
(the menu text) and `/help`/`/start` only** (later tasks land those call
sites — T1 only builds the plumbing). `/status`, `/summary`, `/new`,
`/session`, `/delete`, `/cancel`, `/reload_skills`, every ERR-01 string and
every agent reply stay on the plain path — untouched by this task.

`send_pre` returns the `sendMessage` result (the `message_id` a keyboard
edit needs later) or `None` after OUT-04's fallback also failed;
`edit_pre` likewise returns the `editMessageText` result or `None`.

### REQ-V1110-OUT-03 — `render_table`, a pure function in new module `tables.py`

New file at the **repository root** (not `devtools/`) — it joins
`GATE8_DEPENDENCIES` by the `*.py` glob at repo root, which is intentional
(gate 8 runs once, later, at T7 — this is fine, do not special-case it).

```
tables.render_table(
    headers: Sequence[str],
    rows: Sequence[Sequence[object]],
    *,
    align: Sequence[str] | None = None,
    max_width: Sequence[int | None] | None = None,
) -> str
```

- Cells `str()`-ed; `None` → `n/a`.
- A column's alignment is `"r"` when `align` says so for that column, or
  when every non-`n/a` cell in it is `int`/`float`; else `"l"` (numbers
  right, text left).
- Every text cell longer than its column's `max_width` is truncated:
  truncation consumes UTF-16 units, never splits a Unicode scalar (so an
  astral character like U+1F600 is never cut in half), reserves one UTF-16
  unit for `…`, and guarantees `utf16_length(cell) <= max_width`.
- Each column padded to its widest cell in UTF-16 units.
- `utf16_length` **moves to `tables.py`**; `bot.py` re-imports it from
  there (behaviour and the name `bot.utf16_length` stay the same — do not
  break any existing caller in `bot.py`).
- Header row followed by one rule line of ASCII `-` per column (not
  U+2500).
- Columns joined by two spaces; lines joined by `"\n"` with **no trailing
  newline**.
- **Hard rule**: every line of the output has the same UTF-16 length, and
  every table line is ≤ 72 UTF-16 units. `render_table` raises `ValueError`
  when the rendered width would exceed 72 — this is a guard the tests
  trip, not something an end user sees in this task (later tasks' callers
  must supply `max_width` values that satisfy it; T1 just builds and tests
  the guard itself with deliberately-sized inputs).
- Returns raw, unescaped text — `_pre_text`/`send_pre` do the escaping.
- Payload invariant (tested here and reused by later tasks): no
  body-supplied literal `<`, `>` or `&` appears unescaped inside the
  `<pre>` element; the only literal angle brackets are the single trusted
  `<pre>`/`</pre>` tags; body ampersands occur only as generated HTML
  entities.

### REQ-V1110-OUT-04 — one plain-text fallback on a table-path 400

When `send_message_html` raises `TelegramError` with status 400 (the
existing 401/404 fatal classification stands unchanged), `send_pre` sends
**the same fitted body once more** (the `fitted` half of `_pre_text`'s
return, never the original `body`) through plain `send_message(chat_id,
fitted)` — no tags, no `parse_mode`, no `reply_markup`. Returns that
result; a second failure is logged through `_send`'s existing error-logging
line/pattern and `None` is returned; never a third attempt.

`edit_pre` has the same one-time fallback: a 400 from `edit_message_html`
→ edit once more via plain `edit_message_text(chat_id, message_id,
fitted)`; second failure logged, `None` returned, never a third attempt.
