# tg-agent-bot — implementation specification v0

This document is the complete contract for implementing this repository. It is
self-contained: everything needed to implement, test and accept the work is in
this file or in files it tells you to create. Do not look for other sources.

Every requirement has a stable `REQ-*` id and is tagged `MUST` or `NON-GOAL`.
`MUST` = required for acceptance. `NON-GOAL` = explicitly out of scope for v0;
implementing it is a defect, not a bonus.

Target platform: **Linux only**. Language: **Python**. Package manager: **uv**.

---

## 1. Execution contract

**REQ-EC-01 (MUST)** Work from the repository root — the directory that
contains `docs/spec/spec-v0.md` and `AGENTS.md`. All paths in this document are
relative to that directory. Never create, read or modify anything outside it.

**REQ-EC-02 (MUST)** Before editing any file that already exists, read it first.
Preserve existing content unless this spec says to replace it.

**REQ-EC-03 (MUST)** Create exactly the files listed in section 2. Creating
extra source modules, extra tools, extra configuration knobs or extra
dependencies is a defect.

**REQ-EC-04 (MUST)** Bootstrap, in this order, before anything else:

1. Write `.python-version` and `pyproject.toml` with the exact contents from
   section 3.1.
2. Run `uv lock` **once**. This creates `uv.lock`, which MUST be committed.
   `uv lock` is a bootstrap step, not a gate; do not re-run it unless
   `pyproject.toml` changes.

**REQ-EC-05 (MUST)** Implement test-first, in the order given in section 4:

1. Write the test files listed in section 5 first.
2. Run `uv run --locked pytest` and observe the expected failures (tests fail
   because the modules do not exist yet). Record that you observed them.
3. Implement component by component, re-running the test suite as you go.

**REQ-EC-06 (MUST)** When implementation is complete, run the four gate
commands from section 6 **verbatim**, in the given order. No substitutions, no
"equivalent" invocations, no extra flags, no shell aliases.

**REQ-EC-07 (MUST)** Fix loop: at most **5 total** repair-and-rerun cycles.
One cycle = one fix followed by one complete run of all four gate commands from
the first one. Cycles are counted across the whole task, not per gate. When the
5th cycle ends with a failing gate, stop and emit the blocker template from
section 7.2. Do not start a 6th cycle.

**REQ-EC-08 (MUST)** Finish by emitting the report template from section 7.1
when all four gates exit 0, or the blocker template from section 7.2 otherwise.

**REQ-EC-09 (MUST)** Log every prompt you send to a language model as its own
file `docs/prompts/NN-<slug>.md` (`NN` = zero-padded sequence number). Only
implementation-agent prompts belong there.

**REQ-EC-10 (MUST)** Never write runtime data under `docs/`: no Telegram
messages, no model request/response payloads, no tool output, no environment
values, no tokens. This applies to `docs/prompts/`, `docs/reports/` and every
other path under `docs/`.

**REQ-EC-11 (MUST)** Append one row per implementation stage to
`docs/llm-usage.md`, keeping the existing table columns
(`# | Stage | Model | Tokens in | Tokens out | Cost`). Write `unknown` in any
cell your harness does not expose. Never write a secret value into that file.

**REQ-EC-12 (MUST)** Never commit `.env`, a database file, the sandbox
directory, or any log file. Section 3.2 lists the required `.gitignore`
entries.

**REQ-EC-13 (MUST)** Commit in conventional-commit style
(`feat:`, `fix:`, `test:`, `docs:`, `chore:`), one logical unit per commit.

**REQ-EC-14 (MUST)** Concurrency model: the bot is **single-threaded and
sequential**. Updates are processed strictly one at a time, in the order
Telegram returns them. The only threads in the process are the two output
reader threads created per `exec` invocation (section 3.7). Do not introduce
`asyncio`, thread pools, or parallel update handling.

**REQ-EC-15 (MUST)** Minimality is a graded requirement (see Appendix A, HW-1).
The harness is plain Python plus `httpx` and `python-dotenv`. No bot framework,
no agent framework, no ORM, no HTTP server, no JSON-Schema validation library.

### 3.4 Storage

**REQ-DB-01 (MUST)** `storage.py` opens the database with:

```python
conn = sqlite3.connect(str(db_path), isolation_level=None, timeout=5.0)
conn.row_factory = sqlite3.Row
conn.execute("PRAGMA journal_mode=WAL")
conn.execute("PRAGMA foreign_keys=ON")
```

`isolation_level=None` means autocommit; transactions are explicit
`BEGIN IMMEDIATE` / `COMMIT` / `ROLLBACK`.

**REQ-DB-02 (MUST)** `init_schema(conn)` executes exactly this DDL and is
idempotent (running it twice on the same database is a no-op):

```sql
CREATE TABLE IF NOT EXISTS schema_version (
    id      INTEGER PRIMARY KEY CHECK (id = 1),
    version INTEGER NOT NULL
);

INSERT OR IGNORE INTO schema_version (id, version) VALUES (1, 1);

CREATE TABLE IF NOT EXISTS conversations (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    tg_user_id INTEGER NOT NULL,
    created_at TEXT    NOT NULL,
    active     INTEGER NOT NULL DEFAULT 1 CHECK (active IN (0, 1))
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_conversations_one_active
    ON conversations (tg_user_id) WHERE active = 1;

CREATE TABLE IF NOT EXISTS messages (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    conv_id         INTEGER NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
    turn_id         INTEGER NOT NULL,
    role            TEXT    NOT NULL CHECK (role IN ('user', 'assistant', 'tool')),
    content         TEXT    NOT NULL DEFAULT '',
    tool_calls_json TEXT,
    tool_call_id    TEXT,
    created_at      TEXT    NOT NULL,
    CHECK (
        (role = 'user'      AND tool_calls_json IS NULL AND tool_call_id IS NULL)
     OR (role = 'assistant' AND tool_call_id IS NULL)
     OR (role = 'tool'      AND tool_calls_json IS NULL AND tool_call_id IS NOT NULL)
    )
);

CREATE INDEX IF NOT EXISTS idx_messages_conv ON messages (conv_id, id);

CREATE TABLE IF NOT EXISTS bot_state (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
```

After creating the tables, `init_schema` reads `schema_version.version`. If it
is not `1`, raise `RuntimeError("unsupported database schema version: <n>")`.
Migrations are a NON-GOAL (REQ-NG-12).

**REQ-DB-03 (MUST)** Timestamps are UTC, produced by exactly this helper:

```python
def utc_now_iso() -> str:
    return datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")
```

**REQ-DB-04 (MUST)** System messages are **never stored**. The system prompt is
rebuilt for every request (section 3.9).

**REQ-DB-05 (MUST)** `turn_id` semantics. Within one conversation `turn_id` is a
strictly increasing integer, allocated as
`SELECT COALESCE(MAX(turn_id), 0) + 1 FROM messages WHERE conv_id = ?`.
Messages sharing a `turn_id` form one **indivisible group**. Exactly three
group shapes exist:

| Group | Rows | Written by |
|---|---|---|
| user turn | 1 row, `role='user'` | `add_user_message` |
| tool turn | 1 row `role='assistant'` with `tool_calls_json`, followed by 1 row `role='tool'` per tool call | `add_tool_turn` (one transaction) |
| answer turn | 1 row, `role='assistant'`, `tool_calls_json IS NULL` | `add_assistant_message` |

A `tool` row therefore never starts a group. Every `tool_call_id` present in an
assistant row's `tool_calls_json` MUST have exactly one matching `tool` row in
the same group, in the same order.

**REQ-DB-06 (MUST)** `storage.py` public functions:

```python
def connect(db_path: Path) -> sqlite3.Connection: ...
def init_schema(conn: sqlite3.Connection) -> None: ...
def utc_now_iso() -> str: ...

def get_or_create_active_conversation(conn, tg_user_id: int) -> int: ...
def start_new_conversation(conn, tg_user_id: int) -> int: ...

def add_user_message(conn, conv_id: int, content: str) -> int: ...
def add_assistant_message(conn, conv_id: int, content: str) -> int: ...
def add_tool_turn(
    conn,
    conv_id: int,
    content: str,
    tool_calls: list[dict],
    results: list[tuple[str, str]],   # (tool_call_id, result_content), same order
) -> int: ...

def load_context_messages(conn, conv_id: int, limit: int = 30) -> list[dict]: ...

def get_state(conn, key: str) -> str | None: ...
def set_state(conn, key: str, value: str) -> None: ...
```

All four `add_*` functions return the allocated `turn_id`.

**REQ-DB-07 (MUST)** `start_new_conversation` is transactional:

```sql
BEGIN IMMEDIATE;
UPDATE conversations SET active = 0 WHERE tg_user_id = ? AND active = 1;
INSERT INTO conversations (tg_user_id, created_at, active) VALUES (?, ?, 1);
COMMIT;
```

On any exception, `ROLLBACK` and re-raise. Existing messages are never deleted.

**REQ-DB-08 (MUST)** `add_tool_turn` writes the assistant row and all tool rows
inside one `BEGIN IMMEDIATE` … `COMMIT`. On any exception, `ROLLBACK` — the
group is stored completely or not at all. `tool_calls` is serialised with
`json.dumps(tool_calls, ensure_ascii=False)` in OpenAI wire shape:

```json
[{"id": "call_1", "type": "function",
  "function": {"name": "exec", "arguments": "{\"argv\": [\"uname\", \"-a\"]}"}}]
```

**REQ-DB-09 (MUST)** `load_context_messages` algorithm — implement exactly:

1. Fetch the most recent rows of the conversation, bounded:
   ```sql
   SELECT id, turn_id, role, content, tool_calls_json, tool_call_id
   FROM messages WHERE conv_id = ? ORDER BY id DESC LIMIT 120
   ```
   Reverse the result into ascending `id` order. (120 is a safe superset: the
   window keeps at most 30 messages plus the overhang of one group, and a group
   holds at most 4 rows.)
2. Partition the ascending rows into groups of consecutive equal `turn_id`.
3. Walk groups from newest to oldest with `total = 0`. For each group: if
   `total >= limit`, stop; otherwise prepend the group to the result and add
   `len(group)` to `total`.
   Consequences, both required: the newest group is always included even when it
   alone exceeds `limit`; only the oldest included group may push `total` past
   `limit`.
4. Return the selected rows in ascending `id` order, mapped to provider
   messages:

   | Row | Produced dict |
   |---|---|
   | `role='user'` | `{"role": "user", "content": content}` |
   | `role='assistant'`, `tool_calls_json IS NULL` | `{"role": "assistant", "content": content}` |
   | `role='assistant'`, `tool_calls_json` set | `{"role": "assistant", "content": content, "tool_calls": json.loads(tool_calls_json)}` |
   | `role='tool'` | `{"role": "tool", "tool_call_id": tool_call_id, "content": content}` |

Worked example with `limit=30`. Group sizes oldest→newest:
`[1, 4, 1, 1, 4, 1] + [1] * 24` — 36 rows in 30 groups. Walking newest→oldest:

| Step | Group taken | `total` after |
|---|---|---|
| 1–24 | the 24 trailing size-1 groups | 24 |
| 25 | size-1 group | 25 |
| 26 | size-4 group | 29 |
| 27 | size-1 group | 30 |
| 28 | none — `total >= 30`, stop | 30 |

Window = 30 rows, the oldest of which is a `user` row. Overhang illustration:
had step 27 encountered a size-4 group instead, it would still have been taken
whole (`total` 29 → 33) because the check happens *before* a group is taken,
never in the middle of one. 33 rows is a correct window.

**REQ-DB-10 (MUST)** Invariant, enforced by test: the first message of a window
is never `role='tool'`.

**REQ-DB-11 (MUST)** `bot_state` stores the polling cursor under the key
`last_update_id`, value = `str(update_id)`.

### 3.5 LLM plugin contract

**REQ-LLM-01 (MUST)** `llm/base.py` defines:

```python
@dataclass(frozen=True)
class ToolCall:
    id: str
    name: str
    arguments: str            # raw JSON text as returned by the provider

@dataclass(frozen=True)
class LLMResponse:
    content: str              # "" when the provider returns null/absent
    tool_calls: list[ToolCall]
    finish_reason: str        # "" when absent

class LLMError(Exception):
    def __init__(self, message: str, *, retryable: bool) -> None:
        super().__init__(message)
        self.retryable = retryable

class LLMClient(Protocol):
    def complete(
        self,
        messages: list[dict],
        tools: list[dict] | None,
    ) -> LLMResponse: ...
```

**REQ-LLM-02 (MUST)** Request payload builder in `llm/base.py`:

```python
def build_payload(model: str, messages: list[dict], tools: list[dict] | None) -> dict:
    payload = {
        "model": model,
        "messages": messages,
        "temperature": 0,
        "max_tokens": 1024,
        "stream": False,
    }
    if tools is not None:
        payload["tools"] = tools
        payload["tool_choice"] = "auto"
    return payload
```

When `tools is None` the keys `tools` and `tool_choice` MUST be absent from the
body.

**REQ-LLM-03 (MUST)** Response parser in `llm/base.py`:

```python
def parse_response(data: object) -> LLMResponse
```

- `data` must be a `dict` with a non-empty list `choices`; otherwise raise
  `LLMError("malformed provider response: <what is missing>", retryable=False)`.
- `message = data["choices"][0]["message"]`; must be a `dict`, else the same
  non-retryable error.
- `content = message.get("content") or ""`; coerce to `str`.
- `finish_reason = str(data["choices"][0].get("finish_reason") or "")`.
- For each entry of `message.get("tool_calls") or []`, in order, build a
  `ToolCall`:
  - `id = str(entry.get("id") or "")` (empty is allowed here; the agent
    normalises it — REQ-AG-06),
  - `fn = entry.get("function") or {}`,
  - `name = str(fn.get("name") or "")`,
  - `raw = fn.get("arguments")`; if `raw is None` → `""`; if `raw` is a `str` →
    used as-is; otherwise → `json.dumps(raw, ensure_ascii=False)` (some servers
    return a JSON object instead of a string).
- A response with neither content nor tool calls is **not** an error: return
  `LLMResponse("", [], finish_reason)`.

**REQ-LLM-04 (MUST)** HTTP/error mapping, shared helper in `llm/base.py`:

| Situation | `LLMError.retryable` | Message |
|---|---|---|
| `httpx.TimeoutException` | `True` | `llm request timed out` |
| other `httpx.TransportError` | `True` | `llm transport error: <exception class name>` |
| status 429 | `True` | `llm http 429` |
| status 500–599 | `True` | `llm http <status>` |
| status 400–499 except 429 | `False` | `llm http <status>: <first 200 chars of body>` |
| body is not JSON | `False` | `llm response is not json` |
| `choices` missing/empty, or `message` not an object | `False` | `malformed provider response: <detail>` |

Every message MUST be passed through `config.redact()` before it is put into
the exception. `httpx.TimeoutException` is a subclass of
`httpx.TransportError`; check the timeout case first.

**REQ-LLM-05 (MUST)** `llm/lmstudio.py`:


```json
      "function": {"name": "load_skill", "arguments": "{\"name\": \"host-info\"}"}}]}}]}
```

**REQ-LLM-06 (MUST)** `llm/openrouter.py`:

```python
class OpenRouterClient:
    def __init__(self, api_key: str, model: str, timeout_s: float,
                 client: httpx.Client) -> None: ...
```

- URL: the constant `https://openrouter.ai/api/v1/chat/completions`. There is

### 3.7 Bounded arbitrary execution (`exec`)

#### 3.7.1 Threat model — read this before implementing

**REQ-EXEC-01 (MUST)** The spec, the tool description and `README.md` describe
this feature as **bounded arbitrary execution**, never as "safe exec" or a
"sandbox" in the security sense. The following statements MUST appear in
`README.md` in substance:

- The `exec` tool runs **arbitrary programs** chosen by a language model, with
  the same operating-system privileges as the bot process.
- `cwd`, the environment allowlist, the timeout and the output caps bound
  *resource usage and accident blast radius*. They are **not a security
  boundary**. A program started through `exec` can read any file the bot user
  can read, open network connections, write outside the sandbox directory, and
  start descendants that outlive the process group by calling `setsid`.
- Therefore the bot MUST be run under a **dedicated low-privilege operating
  system account** that owns no SSH keys, no cloud credentials and no personal
  data, and the Telegram whitelist is the primary access control.

Rationale for keeping it universal: the assignment requires a *universal
console tool*. An executable allowlist would satisfy the security concern but
contradict the graded requirement, and it is defeated in practice anyway by any
interpreter on the allowlist. See REQ-NG-01 and REQ-NG-02.

#### 3.7.2 Proven runner

**REQ-EXEC-02 (MUST)** `tools.py` contains this runner. It is a verified
implementation — copy the structure exactly; changing the ordering of the wait,
join and kill steps reintroduces deadlocks that were tested for.

```python
import os
import signal
import subprocess
import threading
from pathlib import Path

EXEC_TIMEOUT_S = 30.0
EXEC_KILL_GRACE_S = 5.0
EXEC_DRAIN_GRACE_S = 2.0
EXEC_MAX_STREAM_BYTES = 4096
_READ_CHUNK = 65536


class _Capture:
    """Bounded, thread-safe sink. Keeps the first `cap` bytes, discards the rest."""

    def __init__(self, cap: int) -> None:
        self._cap = cap
        self._buf = bytearray()
        self._truncated = False
        self._lock = threading.Lock()

    def feed(self, chunk: bytes) -> None:
        with self._lock:
            room = self._cap - len(self._buf)
            if room > 0:
                self._buf += chunk[:room]
            if len(chunk) > room:
                self._truncated = True

    def snapshot(self) -> tuple[bytes, bool]:
        with self._lock:
            return bytes(self._buf), self._truncated


def _drain(stream, sink: _Capture) -> None:
    """Read `stream` to EOF.

    CONTRACT: this MUST keep reading after the cap is reached. Stopping early
    fills the pipe buffer and blocks the child forever.
    """
    try:
        while True:
            chunk = stream.read(_READ_CHUNK)
            if not chunk:
                return
            sink.feed(chunk)
    except (OSError, ValueError):
        return
    finally:
        try:
            stream.close()
        except Exception:
            pass


def _killpg(pgid: int, sig: int) -> None:
    try:
        os.killpg(pgid, sig)
    except (ProcessLookupError, PermissionError, OSError):
        pass


def run_command(
    argv: list[str],
    *,
    workdir: Path,
    timeout_s: float = EXEC_TIMEOUT_S,
) -> dict:
    # CONTRACT: Popen raises FileNotFoundError for BOTH a missing program and a
    # missing cwd. Check the cwd first so the two never share an error message.
    if not workdir.is_dir():
        return {"error": "sandbox directory is missing"}
    env = {
        "PATH": os.environ.get("PATH", "/usr/local/bin:/usr/bin:/bin"),
        "LANG": os.environ.get("LANG", "C.UTF-8"),
        "HOME": str(workdir),
    }
    try:
        proc = subprocess.Popen(
            argv,
            cwd=str(workdir),
            env=env,
            stdin=subprocess.DEVNULL,
            stdout=subprocess.PIPE,
            stderr=subprocess.PIPE,
            shell=False,
            start_new_session=True,
            bufsize=0,
        )
    except FileNotFoundError:
        return {"error": f"program not found: {argv[0]}"}
    except PermissionError:
        return {"error": f"permission denied: {argv[0]}"}
    except OSError as exc:
        return {"error": f"failed to start process: {exc.__class__.__name__}"}

    # CONTRACT: start_new_session=True makes the child a process-group leader,
    # so pgid == proc.pid. Capture it now: os.getpgid() raises after the child
    # is reaped.
    pgid = proc.pid
    out, err = _Capture(EXEC_MAX_STREAM_BYTES), _Capture(EXEC_MAX_STREAM_BYTES)
    t_out = threading.Thread(target=_drain, args=(proc.stdout, out), daemon=True)
    t_err = threading.Thread(target=_drain, args=(proc.stderr, err), daemon=True)
    t_out.start()
    t_err.start()

    timed_out = False
    try:
        proc.wait(timeout=timeout_s)
    except subprocess.TimeoutExpired:
        timed_out = True
        _killpg(pgid, signal.SIGTERM)
        try:
            proc.wait(timeout=EXEC_KILL_GRACE_S)
        except subprocess.TimeoutExpired:
            _killpg(pgid, signal.SIGKILL)
            proc.wait()

    # The direct child is reaped. Descendants may still hold the pipe write
    # ends open; give them a short grace period, then kill the whole group so
    # the reader threads reach EOF.
    t_out.join(timeout=EXEC_DRAIN_GRACE_S)
    t_err.join(timeout=EXEC_DRAIN_GRACE_S)
    if t_out.is_alive() or t_err.is_alive():
        _killpg(pgid, signal.SIGKILL)
        t_out.join(timeout=EXEC_DRAIN_GRACE_S)
        t_err.join(timeout=EXEC_DRAIN_GRACE_S)

    out_bytes, out_trunc = out.snapshot()
    err_bytes, err_trunc = err.snapshot()
    return {
        "exit_code": proc.returncode,
        "timed_out": timed_out,
        "truncated": out_trunc or err_trunc,
        "stdout": out_bytes.decode("utf-8", errors="replace"),
        "stderr": err_bytes.decode("utf-8", errors="replace"),
    }
```

**REQ-EXEC-03 (MUST)** Semantics that tests assert:

- Caps are applied to **bytes first, then decoded** with `errors="replace"`.
  Decoding first and slicing characters is wrong and produces different output.
- `truncated` is a single envelope field meaning "either stream was truncated".
- When `timed_out` is `True`, `exit_code` is `proc.returncode` and is
  **negative** (`-15` for SIGTERM, `-9` for SIGKILL). Tests assert
  `timed_out is True and exit_code < 0`, never an exact value, except for the
  TERM-ignoring case which is exactly `-9`.
- `stdin` is `/dev/null`; a program that reads stdin gets EOF immediately.
- The child's environment contains only `PATH`, `LANG` and `HOME`, and `HOME`
  equals the sandbox directory.
- Descendants that call `setsid` leave the process group and are **not** killed.
  This limitation is documented in `README.md` and is a NON-GOAL to fix
  (REQ-NG-02).

```
    except LLMError as exc:
```

`sleep(RETRY_SLEEP_S)` runs **only when a retry will actually be attempted** —

attempts, **exactly one retry is available per user message**. The first
retryable failure consumes it; a later retryable failure ends the turn with

**REQ-AG-07 (MUST)** Execution and budget rules for one response:

1. `executable = normalized[:MAX_TOOL_CALLS_PER_RESPONSE]`,

2. For each call in `executable`, in order:

     `result = execute_tool(call.name, call.arguments, skills=skills, runner=runner)`

     "answer with the information you already have"})`, and `tools_used` is
     **not** incremented.

success, argument-validation error or unknown tool name all count. Excess calls
and calls rejected because the budget was already exhausted consume nothing.
This keeps the budget monotone and makes the transition table computable.

**REQ-AG-08 (MUST)** Budget transition table. `A` = attempts already used
before the call, `T` = `tools_used` before the round.

| Round | `T` | Tools exposed | Extra system message | Retryable error → | Non-retryable error → |
|---|---|---|---|---|---|
| 1–7 | `T < 12` | `exec`, `load_skill` | none | retry the same round with the same tool policy if `A + 1 < 9`, else `FALLBACK_LLM_ERROR` | `FALLBACK_LLM_ERROR` |
| 1–7 | `T == 12` | none (`tools=None`) | `FINAL_INSTRUCTION` | same | same |
| 8 | any | none (`tools=None`) | `FINAL_INSTRUCTION` | same | same |
| >8 | any | unreachable | — | — | `FALLBACK_NO_ANSWER` |

### 3.11 Telegram layer

**REQ-TG-01 (MUST)** `bot.py` defines:

```python
class TelegramError(Exception):
    def __init__(self, message: str, *, retry_after: float | None = None,
                 fatal: bool = False) -> None: ...

class TelegramClient:
    def __init__(self, token: str, *, client: httpx.Client) -> None: ...
    def call(self, method: str, payload: dict, *, read_timeout: float) -> dict: ...
    def get_me(self) -> dict: ...
    def get_updates(self, offset: int | None) -> list[dict]: ...
    def send_message(self, chat_id: int, text: str) -> None: ...
```

**REQ-TG-02 (MUST)** `call()`:

- URL is `f"https://api.telegram.org/bot{self._token}/{method}"`. It is
  **never** logged or included in an exception message.
- `timeout = httpx.Timeout(connect=10.0, read=read_timeout, write=10.0,
  pool=10.0)`.
- `self._client.post(url, json=payload, timeout=timeout)`.
- Disposition:

| Situation | Result |
|---|---|
| `httpx.TimeoutException` / `httpx.TransportError` | `TelegramError("telegram <method> transport error: <exception class name>")` |
| HTTP 401 or 404 | `TelegramError("telegram <method> rejected the bot token", fatal=True)` |
| HTTP 429 | `TelegramError("telegram <method> rate limited", retry_after=<from body>)` |
| other non-200 status | `TelegramError("telegram <method> http <status>")` |
| body is not JSON | `TelegramError("telegram <method> returned non-json")` |
| JSON with `ok` not `true` | `TelegramError("telegram <method> api error <error_code>: <description>")`, with `retry_after` taken from the body when `error_code == 429` |
| JSON with `ok: true` | return `data["result"]` |

  `retry_after` is read as `float(body["parameters"]["retry_after"])` when
  present and parseable, otherwise `None`.
- Every message is passed through `config.redact()` before the exception is
  raised.

**REQ-TG-03 (MUST)** `get_updates(offset)` posts to `getUpdates` with body
`{"timeout": 50, "allowed_updates": ["message"]}` plus `"offset": offset` when
`offset is not None`, and `read_timeout=60.0`. The read timeout MUST be larger
than the long-poll timeout. `get_me` and `send_message` use
`read_timeout=20.0`.

**REQ-TG-04 (MUST)** `main()` startup order:

1. `logging.basicConfig` (REQ-PATH-04).
2. `cfg = load_config()`; on `ConfigError` log the message and return exit
   code `2`.
3. `conn = storage.connect(cfg.db_path)`, `storage.init_schema(conn)`.
4. `skills = tools.load_skills(PROJECT_ROOT / "skills")`.
5. `client = httpx.Client()`; `tg = TelegramClient(cfg.telegram_bot_token,
   client=client)`.
6. `bot_username = tg.get_me()["username"]` — cached for the whole run. If
   `get_me` fails, log the redacted reason and return exit code `2` (the
   username is required for correct `/new@bot` handling).
7. `llm = build_llm_client(cfg, client=client)`.
8. Enter `poll_loop`.

**REQ-TG-05 (MUST)** `poll_loop` behaviour:

```
raw = get_state(conn, "last_update_id")
offset = int(raw) + 1 if raw is not None else None
backoff_attempt = 0
while not shutdown_requested:
    try:
        updates = tg.get_updates(offset)
    except TelegramError as exc:
        if exc.fatal: log; return 2
        backoff_attempt += 1
        sleep(exc.retry_after + 1.0 if exc.retry_after is not None
              else min(1.0 * 2 ** (backoff_attempt - 1), 30.0)
                   + random.uniform(0.0, 0.5))
        continue
    backoff_attempt = 0
    for update in updates:
        process_update(update, ...)
        offset = update["update_id"] + 1
```

`retry_after` always takes precedence over the generic backoff. The backoff
counter resets after any successful `getUpdates`.

**REQ-TG-06 (MUST)** `process_update` — the single entry point for one update:

```python
def process_update(update: dict, *, conn, tg, cfg, llm, skills, runner,
                   bot_username: str) -> None: ...
```

1. If `update` is not a `dict`, or `update.get("update_id")` is not an `int`,
   log `WARNING update without a usable update_id ignored` and return **without
   advancing the cursor** (there is nothing to advance to).
2. `storage.set_state(conn, "last_update_id", str(update_id))` — **before any
   other effect**. This is the at-most-once boundary (REQ-TG-11).
3. Filtering, in this exact order; each rule logs one line and returns:
   - `update.get("message")` missing or not a `dict` → ignore (edited messages,
     callback queries, channel posts).
   - `message["chat"]["type"] != "private"` → ignore.
   - `message.get("from")` missing, or `from.get("is_bot")` is truthy → ignore.
   - `from["id"]` not in `cfg.allowed_tg_ids` → log
     `WARNING unauthorized update from tg_id=<id>` and ignore. **Nothing else
     happens: no conversation is created, no message is stored, no inference
     runs, no command executes, no reply is sent.** Only the cursor written in
     step 2 changed.
   - `message.get("text")` missing, not a `str`, or empty after strip → send
     the fixed text `I can only process plain text messages.` and return
     without storing anything.
4. Command handling on `text.strip()`:
   - If it starts with `/`: take the first whitespace-separated token,
     `cmd, _, suffix = token.partition("@")`.
     - If `suffix` is non-empty and `suffix.casefold() != bot_username.casefold()`
       → the command is addressed to another bot: ignore entirely (no reply, no
       storage).
     - Else if `cmd.casefold() == "/new"` → `storage.start_new_conversation`,
       reply exactly `New conversation started.`, and return. Any arguments
       after `/new` are ignored. The `/new` text itself is **not** stored in
       `messages`.
     - Otherwise the text is handled as an ordinary message (REQ-NG-08).
5. Ordinary text:
   1. `conv_id = get_or_create_active_conversation(conn, from_id)`
   2. `add_user_message(conn, conv_id, text)`
   3. `now = storage.utc_now_iso()`
   4. `reply = run_agent(conn=conn, conv_id=conv_id, llm=llm, skills=skills,
      runner=runner, now=now)`
   5. `for part in split_message(reply): tg.send_message(chat_id, part)`

**REQ-TG-07 (MUST)** `split_message(text, limit=4096) -> list[str]` counts
**UTF-16 code units**, which is what Telegram counts: a character contributes
`2` when `ord(ch) > 0xFFFF`, otherwise `1`. Accumulate characters and cut when
adding the next character would exceed `limit`. The cut is a hard cut — no
word- or line-boundary preference. `split_message("")` returns `[]` and no
message is sent.

**REQ-TG-08 (MUST)** Multi-part sending is sequential and ordered. If part `k`
fails after parts `1..k-1` succeeded, log the redacted error, stop sending the
remaining parts, and continue the polling loop. Partial delivery is an accepted
consequence of at-most-once (REQ-TG-11).

**REQ-TG-09 (MUST)** `run_agent` is never called for unauthorized senders,
non-private chats, bot senders, non-text messages, or `/new`.

**REQ-TG-10 (MUST)** Graceful shutdown: a module-level `_shutdown` flag is set
by handlers registered for `SIGINT` and `SIGTERM`; the poll loop checks it at
the top of every iteration. `KeyboardInterrupt` raised inside the loop is also
caught. On shutdown: log `shutting down`, close the httpx client and the
database connection, return exit code `0`.

**REQ-TG-11 (MUST)** Delivery semantics — state this in `README.md` and prove
it with a test (T-TG-08):

> Processing is **at-most-once**. The polling cursor is persisted before any
> side effect of that update. A crash between persisting the cursor and sending
> the reply loses that one reply; the update is never processed twice.
> Exactly-once delivery is **not** provided and is not claimed. An outbox or
> idempotency table is a NON-GOAL (REQ-NG-04).

**REQ-TG-12 (MUST)** Persistence sequence for one ordinary text update, and the
partial histories it can leave behind:

| Step | Transaction | Possible partial state after a crash |
|---|---|---|
| cursor write | own | update is skipped after restart; nothing else stored |
| conversation upsert | own | conversation exists with no messages |
| user message | own | a user message with no assistant reply |
| each tool turn | one per turn | history ends with a complete tool turn |
| final assistant message | own | answer stored but never delivered |

Each of those states is valid input to `load_context_messages` — no repair pass
exists and none is required.

## 6. Gates

**REQ-GATE-01 (MUST)** Run these four commands, verbatim, in this order, from
the repository root. All four MUST exit `0`.

```bash
uv sync --locked
uv run --locked ruff check .
uv run --locked pytest
```

**REQ-GATE-02 (MUST)** `uv lock` is a one-time bootstrap step (REQ-EC-04), not
a gate. If `uv sync --locked` reports that the lock file is out of date, the
correct fix is to re-run `uv lock` and count that as one fix cycle.

**REQ-GATE-03 (MUST)** No gate may be replaced by a narrower command
(`pytest tests/test_x.py`, `ruff check bot.py`, a direct `python bot.py`
invocation without `uv run --locked`, and so on). Narrower commands are fine
*during* development; acceptance is the four commands above.
